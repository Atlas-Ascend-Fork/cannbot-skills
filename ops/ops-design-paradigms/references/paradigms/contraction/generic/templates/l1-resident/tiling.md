# contraction 单侧 L1 驻留模板：Tiling 设计

选块流程见 [公共选块](../../tiling-selection.md)；本模板提供实际任务、数据复用及资源模型，使用与其搬运方式匹配的成本公式。

场景、槽数和贯穿实例见 [DAG 与 Buffer](dag-buffers.md)。先证明整矩阵可以驻留，再求流式侧的块尺寸；不能先套基础模板的 A/B 对称预算。

记 `Span(layer,shape,type,layout)` 为选定布局包含 padding 的单槽字节跨度，`Capacity(layer)` 为目标能力提供的可用容量。槽间对齐和保留区域计入 `Reserved(layer)`；目标容量与布局要求引用[公共资源契约](../../common-contract.md#3-资源描述)。

## 1 UB 切分

不涉及。

## 2 L1 切分

### 2.1 驻留侧与流式侧

B 驻留范围为完整 `[K,N]`，每个参与核持有独立副本；A 的窗口为 `[ML1,KL1]`。本例 `ML1=ML0`，输出任务沿 M 分条带，条带内 N 切成 NL0 输出块。`NL1=N` 描述驻留/任务范围，不能用 NL0 替换整份 B 的容量。

```text
BResidentBytes = Span(L1, (K, N), Tin, BLayoutL1)
AStreamSlotBytes = Span(L1, (ML1, KL1), Tin, ALayoutL1)
BResidentBytes + 2*AStreamSlotBytes + Reserved(L1) <= Capacity(L1)
```

如果整份 B 加最小合法 A 窗口仍不满足容量，就不选择本模板。只驻留一个 N 窗口属于另一种复用范围，不能把其资源需求拿来证明本模板可行。

### 2.2 窗口选择

从满足通路及布局对齐的候选 KL0 出发，枚举 KL1 为合法的 KL0 多段窗口，再联合 ML1、NL0 检查各层容量与任务数。尾部使用实际有效长度，物理跨度仍按选定布局计算。增大 KL1 可减少流式搬运次数，但会挤占完整 B 所需的 L1 空间。

## 3 L0A 切分

`2*Span(L0A,(ML0,KL0),Tin,ALayoutL0) + Reserved(L0A) <= Capacity(L0A)`。A 从当前 L1 窗口取子窗口；本例 ML0=ML1=64、KL0=64。K 子窗口的 L0 目的坐标从零开始。

## 4 L0B 切分

`2*Span(L0B,(KL0,NL0),Tin,BLayoutL0) + Reserved(L0B) <= Capacity(L0B)`。B 源视图保留完整驻留矩阵的父布局；NL0=64 不改变 B L1 的 N=128 或 K=256 父跨度。

## 5 L0C 切分

`Span(L0C,(ML0,NL0),Tacc,CLayoutL0) + Reserved(L0C) <= Capacity(L0C)`。每个输出块独占一槽完成完整 K，输出消费结束后交给下一个 N 子块或下一个任务。不能把 `[ML1,N]` 整个条带的部分和误计为同时存活。

## 6 BiasTable 切分

原无组合扩展实例不涉及。启用 Elementwise/Broadcast Bias[N] 组合扩展时，按 [Bias[N] 组合扩展策略](../../execution-strategies.md#8-biasn-组合扩展的首段融合策略) 分配 BiasTable 槽，并将中转槽记入 L1；增加资源后重新筛选分块。

## 7 多核切分

### 7.1 任务定义与复用域

本例一个任务是一个 M 条带：`taskCount=ceil(M/ML1)=10`。任务 `taskId` 对应 `mTaskOffset=taskId*ML1`，覆盖所有 N；任务内 `nL0Offset=0,NL0,...` 逐块输出。四核按 `taskId=coreId+taskRound*coreCount` 分配。

| 核 | taskId | M 起点 | 每个任务内 N 起点 |
|---|---|---|---|
| 0 | 0、4、8 | 0、256、512 | 0、64 |
| 1 | 1、5、9 | 64、320、576 | 0、64 |
| 2 | 2、6 | 128、384 | 0、64 |
| 3 | 3、7 | 192、448 | 0、64 |

十个条带、二十个输出块，恰好覆盖 `[640,128]`。基础模板将任务分配与 SWAT 坐标映射分开；本模板在任务层只有一个 N 条带，SWAT 的二维映射退化为沿 M 枚举。条带内 N 子块是核内循环，不额外分派到其他核。

复用域是“同一核持有同一 B 的全部任务”，不是一个输出块，也不是共享片上存储的跨核协作。B 不随 taskRound、M 或 N 子块改变。矩阵身份变化时必须结束旧复用域并重新预载。

### 7.2 并行度与搬运量

每核 B 搬运量为一份完整矩阵，总体为 `activeCoreCount*BResidentBytes`，其中 `activeCoreCount=min(coreCount,taskCount)`。A 在每个 N 输出块重新遍历完整 K；逻辑有效搬运量约为 `ceil(N/NL0)*M*K*sizeof(Tin)`。与基础双流式方案比较时，同时考虑 B 跨任务复用次数、整份矩阵重复到各核的成本，以及条带数量是否足够使用核。

本例四核预载 B 共 262144 字节，A 共 `2*640*256*2=655360` 字节，输入合计 917504 字节；C 输出 163840 字节。核 0/1 各有六个输出块，核 2/3 各四个：前者各读 196608 字节 A 加 65536 字节 B，后者各读 131072 字节 A 加 65536 字节 B。不能将每核 B 预载平均到全局二十块后忽略最慢核。实际物理搬运还需计入 padding 与通路参数。

## 8 切分策略微调

### 8.1 A 驻留的对称变化

A 整矩阵 `[M,K]` 驻留一槽，B `[KL1,NL1]` 流式两槽；令 `ML1=M,NL1=NL0`，任务沿 N 分条带，任务内沿 M 切 ML0 输出块。容量式交换驻留/流式角色，L0A/B 各自按自己的布局重算，不通过交换 GM 指针代替布局转换。所有权、父布局偏移和最后消费者规则保持相同结构。

### 8.2 缓存与预载

B 在本核只从 GM 搬一次，但其他核可能读取同一数据；其 L2 重访与流式 A 的访问频度不同。cache hint 分别按两类访问选择，并遵守[公共资源契约](../../common-contract.md#3-资源描述)。L1 驻留不意味着 L2 永久保留，也不要求将所有访问设置相同 hint。

## 9 整体切分流程

1. 从归一化输入确定驻留侧及完整矩阵的物理跨度，剔除无法容纳驻留数据与最小流式窗口的方向。
2. 按[公共选块流程](../../tiling-selection.md#2-候选生成与合法性)枚举合法 ML0、NL0、KL0、KL1，使用本模板的非对称资源式检查各层独立容量。
3. 生成条带任务及核内输出块，计算各核一次预载、重复流式搬运、L0 搬运和输出的工作量，再按公共成本模型展开流水完成时间。
4. 使用选定评价策略的候选顺序、比较与同分规则选出配置；没有合法驻留配置时进入其他模板候选。
5. 绑定固定槽分配、输出交接方式、任务范围与有效长度，并执行 §11 校验。

贯穿实例给出一套合法配置及其资源、地址和成本展开；模型参数和候选规则属于所选评价策略的输入。

## 10 切分后处理

### 10.1 UB 大小计算

不涉及。

### 10.2 Workspace 分配

不涉及。

### 10.3 TilingKey 设置

驻留侧改变代码路径时作为策略维度，与 [A/B 存储方向](../../template-overview.md#3-tilingkey) 分开选择；不为运行时尺寸数值增加同义 key。输出固定 C[M,N]。

### 10.4 TilingData 设置

绑定 M/N/K、分层窗口、实际核数、GM 步长、驻留父布局及槽跨度的消费者；可由同一源字段推导的信息不另造镜像字段。使用后端已有 Params 时校验派生值一致。

### 10.5 ScheduleMode 设置

选择实际纯 Cube 实例所需的任务类型和调度设置；每核独立驻留无需额外跨核同步。

### 10.6 资源约束的输入与实例分配

容量与对齐从公共资源契约获取，逐层检查 DAG §2.1 的需求账本；不得把其他核空闲 L1 计入当前核预算。条带和输出块尺寸分别绑定，防止按完整 N 分配或写回单次 L0C。

本例采用无额外 padding 的布局，以下为各存储层内相对字节区间；各层地址空间独立，目标绑定还须满足起址约束。

| 存储层 | 槽区间 |
|---|---|
| L1 | A0 `[0,16384)`；A1 `[16384,32768)`；驻留 B `[32768,98304)` |
| L0A | 槽0 `[0,8192)`；槽1 `[8192,16384)` |
| L0B | 槽0 `[0,8192)`；槽1 `[8192,16384)` |
| L0C | 槽0 `[0,16384)` |

以上区间是本例需求分配，不是硬件固定分区。尾窗口不改变已分配槽间距；驻留 B 的位置由流式 A 的全部槽预留决定。

## 11 切分策略产出校验

覆盖仅一个任务、多任务/核、少于核数的任务、M/N/K 尾部、单/多 K 窗口，以及整矩阵恰好容纳和超出容量的两侧边界。A 驻留镜像检查 N 条带与 M 内循环。类型与转置更换后重新计算父布局跨度、合法切片和所有字节地址。

## 12 双侧完整 K 面板驻留的切分

实例定义见 [DAG §3](dag-buffers.md#3-双侧完整-k-面板驻留变体)。先选择输出任务矩形，再核算 `SpanAL1(ML1,K)+SpanBL1(K,NL1)<=L1Available`；完整 K 不满足时改回流式候选，不能悄悄用 KL0 替换 K 来通过容量判断。

L0A/B分别满足 `2*SpanL0A(ML0,KL0)`、`2*SpanL0B(KL0,NL0)` 的层内预算；单L0C为 `SpanL0C(ML0,NL0,Tacc)`。示例无额外padding时，L1两面板各16KiB、合计32KiB；L0A/B各8KiB；L0C为4KiB。一次驻留的数据供四个输出块复用，不将四个结果全部计为同时占用L0C。

任务仍为 M/N 矩形，可复用基础 SWAT 坐标映射和核内多任务分配。预载和释放以任务为单位；这与单侧整矩阵跨全部任务驻留的复用域不同。地址和同步按 [Kernel §11](kernel-template.md#11-双侧完整-k-面板的地址与执行) 绑定。筛选时同时比较面板重复搬运量、局部复用次数、核数及全K空间需求，不因“全载”名称假定更快。

## 13 可选 bias 的分派与切分

原贯穿实例保持 hasBias=false；组合扩展启用时输入仍是共享的一维 `[N]` 向量。A 驻留时各 N 块按真实向量 N 区间读取；B 驻留时不同 M 块可重用同一 N 区间；其他保留轴坐标也复用该向量。

`hasBias` 参与编译期 TilingKey 分派；Params 承接唯一 Bias[N] 输入的地址、N 方向真实 stride、槽基址与跨度，不定义逐坐标 bias 输入。BiasTable 按当前输出列块的物理跨度预留。目标布局和容量仍须逐层验证。

bias 复用域独立于 A/B 驻留域；每个条带内输出块仍独立首段注入，驻留值不表示已经为新输出加入 bias。
