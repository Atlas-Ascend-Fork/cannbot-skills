# contraction 范式 basic Tiling 策略

公共不变量见 [Contraction 公共契约](../../common-contract.md)；本页负责基础模板的具体实例与策略。

## 1 UB 切分

不涉及。

## 2 L1 切分

### 2.1 切分原理

根据 [DAG 存活节点](dag-buffers.md#121-逻辑存活节点)，L1 的逻辑节点为 A/B 两个输入窗口，物理节点为 A/B 各两个 buffer。固定 ML1/NL1 后，KL1 决定一次搬入的 K 窗口及每槽占用；A 沿 N 复用，B 沿 M 复用。

### 2.2 切分公式

令 `inputElemBytes=sizeof(Tin)`、`accElemBytes=sizeof(Tacc)`。A/B 单槽逻辑字节分别为 `inputElemBytes*ML1*KL1`、`inputElemBytes*KL1*NL1`。按选定布局计入 padding 后，分别得到物理跨度 `aL1SlotBytes`、`bL1SlotBytes`：

- aL1SlotBytes <= A_L1 单槽可用字节。
- bL1SlotBytes <= B_L1 单槽可用字节。
- 两份 A 与两份 B 的预留跨度、间隙合计 <= L1 可用字节。

固定 stage 分区时还要检查每个 stage 的 A/B 合计；总量合法不代替单 stage 合法。布局跨度计算见 [Kernel 布局推导](kernel-template.md#34-贯穿实例的片上布局公式)。

### 2.3 窗口边界

每轮有效 K 为 `min(KL1,K-kL1Offset)`，物理预留槽保持固定。M/N 尾部取有效行列，读取对齐区域时须有合法存储及正确填充值。转置改变物理连续方向，应重新计算搬运步长和布局跨度。

## 3 L0A 切分

### 3.1 切分原理与公式

L0A 有一个 A 计算输入逻辑节点、两个物理 buffer。单槽逻辑窗口为 `[ML1,KL0]`，逻辑字节为 `inputElemBytes*ML1*KL0`，物理跨度由输入类型和 L0A 布局决定。

- aL0SlotBytes <= L0A 单槽可用字节。
- 两个 A 槽的实际预留范围 <= L0A 可用地址范围。

固定 ML1 后，用该约束求 KL0 的合法范围。每段有效 KL0 不超过当前 L1 窗口剩余 K；复用槽前等待上一乘加读取完成。

## 4 L0B 切分

### 4.1 切分原理与公式

L0B 有一个 B 计算输入逻辑节点、两个物理 buffer。单槽逻辑窗口为 `[KL0,NL1]`，逻辑字节为 `inputElemBytes*KL0*NL1`，物理跨度由输入类型和 L0B 布局决定。

- bL0SlotBytes <= L0B 单槽可用字节。
- 两个 B 槽的实际预留范围 <= L0B 可用地址范围。

固定 NL1 后求 KL0 的合法范围，并与 L0A 的范围及目标 K 对齐要求取交集。A/B 必须使用同一个逻辑 K 区间参与乘加；两块存储的容量分别检查。

## 5 L0C 切分

### 5.1 切分原理与公式

L0C 有一个 C 部分和逻辑节点；物理槽数由 [L0C 选择](../../execution-strategies.md#4-l0c-选择与结果交接) 决定，本例为一个。单槽逻辑窗口为 `[ML1,NL1]`，逻辑字节为 `accElemBytes*ML1*NL1`：

- cL0SlotBytes <= L0C 单槽可用字节。
- C 槽的实际预留范围 <= L0C 可用地址范围。

ML1/NL1 的候选同时满足此约束、L0A/B 输入约束和输出任务并行度要求。C 在完整 K 累加期间保持存活，KL1/KL0 分段不增加 C 的份数。输出类型 Tout 影响写回字节数，不替代 Tacc 的槽容量。

## 6 Bias[N] 组合扩展的 BiasTable 切分

原无组合扩展实例不涉及。hasBias=true 时按 [Bias[N] 组合扩展首段融合策略](../../execution-strategies.md#8-biasn-组合扩展的首段融合策略) 分配 BiasTable 槽，并将中转槽记入 L1；增加资源后重新筛选分块。

## 7 多核切分

### 7.1 切分原理

M/N 输出块之间无依赖，一个核拥有该块完整 K。本模板采用沿 M 分组、组内 M 优先、相邻组 N 反向、末组吸收余数的 SWAT 映射；核间按任务编号轮转。完整算法见 [SWAT 调度](../../swat-scheduler.md#2-分组蛇形映射)。

### 7.2 切分公式

先计算父任务网格 `mTileCount=ceil_div(M,ML1)`、`nTileCount=ceil_div(N,NL1)`，再按 [SWAT 分组映射](../../swat-scheduler.md#2-分组蛇形映射) 取得块坐标。常规窗口宽度为 4；沿 M/N 的元素起点和有效长度由 [边缘再均衡](../../swat-scheduler.md#3-矩阵边缘再均衡) 求出。

输入转置改变 GM 步长与搬运约束，C 按 [M,N] 写回，调度仍针对逻辑 M/N。尾轮拆分选择见 §7.4；最终任务数、核数和坐标一起生成。

### 7.3 特殊场景

检查任务少于核数、多轮任务和最后一轮部分核工作。无任务核安全退出，本实例不需要全核 barrier。M/N 尾块按有效区域写回，不能覆盖相邻块。

### 7.4 SWAT 的可选尾轮重新切分

矩阵边缘尾块由 M/N 尺寸余数产生，调度尾轮由任务数相对于核数的余数产生。两种调整分开计算；本例矩阵边缘不再均衡，尾轮拆分由下述规则选出。

#### 7.4.1 拆分份数选择

采用 [公共尾轮拆分份数选择](../../tiling-selection.md#9-尾轮拆分份数选择)，输入原父任务数、核数、常规 M/N 块尺寸、输入方向及搬运粒度阈值。本页只代入贯穿实例，不维护另一份搜索过程。

#### 7.4.2 子任务映射

使用 [SWAT 尾轮分派](../../swat-scheduler.md#4-尾轮分派与拆分)：先归一化拆分份数，再由核号求父任务和 M/N 子编号。沿各轴用向上取整的子步长求起点与有效长度；父矩形来自边缘再均衡后的尺寸，空子块跳过。任务编号保留核间分派关系，不另建通用矩形展开列表。

#### 7.4.3 启用拆尾的贯穿实例

本例 T=6、P=4、r=2，A 不转置。首次循环使 mTailParts=2，继续增加 N 会使 2×2×2>4，继续增加 M 也超核数，因此 nTailParts=1。末块 128 按两份归一化后仍为两份，每份 64。前四个任务不变；父任务 4/5 被以下子任务替换：

| 展开任务 | 父任务 | M 起点 | N 起点 | M/N 有效长度 | 核/轮次 |
|---:|---:|---:|---:|---|---|
| 4 | 4 | 0 | 256 | 64/128 | 0/1 |
| 5 | 4 | 64 | 256 | 64/128 | 1/1 |
| 6 | 5 | 128 | 256 | 64/128 | 2/1 |
| 7 | 5 | 192 | 256 | 64/128 | 3/1 |

各子任务 K 仍为 640；不是把同一 C 块的 K 拆给四个核。若目标不接受这组内部边界，则筛掉该候选，按合法边界重新求解。

#### 7.4.4 资源、选择与验收

本策略按 §7.4.1 的确定规则选择拆分方向；末轮最长任务时长、复制输入量、输出对齐、发射开销和缓存重访用于评价该策略，不在执行前再用未定义的成本比较修改份数。贯穿例沿 M 拆分后，尾轮 B 的逻辑读取量从 `2*K*128` 增至 `4*K*128` 个元素；A 总有效读取量不变。L2 hint 依据这种重访模式和接口能力决定，不能仅由“尾块”二字决定关闭缓存。无尾轮或不满足拆分阈值时保持原份数；若另选成本驱动策略，须独立定义其候选及比较规则。

各层槽数与基础流水保持一致，每核按全部任务的最大物理跨度分配；本例首轮仍有128×128任务，不能按尾轮64×128缩小固定槽跨度。子任务独立完成完整K，不分配部分和Workspace。

验证父任务被替换而非重复执行；子任务两两不交且并集等于父区域。覆盖双轴拆分、对齐后实际子任务数减少、边缘尾块与尾轮相交、少于核数及多任务/核。实际scheduler的字段、任务数和launch一起绑定；只在改变编译路径时增加策略key。

## 8 切分策略微调

### 8.1 微调方式

| 选择 | 要解决的问题 | 必须同时检查 |
|---|---|---|
| ML1/NL1 | A/B 复用与输出并行度 | L0C、输入槽、尾块浪费 |
| KL1 | GM 搬运粒度和 L1 复用 | 单 stage 容量、bank、预取距离 |
| KL0 | MTE1/MMAD 粒度 | L0 槽容量、发射开销和尾段 |
| 输出块遍历顺序 | 相邻任务复用 A 或 B 的机会 | 输出所有权保持不变、负载均衡 |
| A/B 的 L2 cache hint | 缓存保留与流式访问取舍 | 实际复用距离、工作集与目标支持 |

L2 中的跨任务复用是机会，不等价于明确保存在 L1 的复用。蛇形/窗口遍历与 cache hint 是两项不同决策；前者改变访问顺序，后者提供缓存策略提示，都不保证命中。本实例先沿用后端默认 hint；只有访问分析与同条件测量支持时才改变 A/B 各自策略，不写“大矩阵一律 bypass L2”等规则。

### 8.2 SWAT 的缓存复用分析

SWAT 第一轮 taskId=0/1 访问同一 B 列块和两个 A 行块，taskId=2/3 访问下一 B 列块并重访这两个 A 行块；第二轮 taskId=4..7 访问第三 B 列块，分别读取四个 64 行的 A 子块。每个 A 元素仍参与三个 N 块的计算，前两个 B 列块分别由两个任务读取，第三个 B 列块由四个尾轮子任务读取。因此保留默认 L2 hint 有明确的复用理由；实际跨核开始时间、容量竞争和缓存实现决定能否命中。BF16 数值例中 A 为 320 KiB、B 为 480 KiB 只是输入总字节，不能据此断言全部常驻 L2。

## 9 整体切分流程

### 9.1 贯穿实例：如何得到一个候选

本模板使用 [公共选块流程](../../tiling-selection.md)，M/N 比较采用其中的 [双侧流式联合策略](../../tiling-selection.md#5-双侧流式的计算访存与均衡联合策略)。执行组织为双侧流式输入、完整 K 累加、直接输出；任务由 SWAT 分配。q 的搬运模型以每个输出块独立搬入 A/B 为前提，尾轮重复读取计入均衡与成本检查。

实例参数还包括两份 L1 A/B 槽、两份 L0A/B 槽和单 L0C。候选首先满足 §2–§5 的分层空间约束；选定 M/N 后确定 KL0、尾轮任务及 KL1，再按实际任务检查有效数据与固定槽跨度。

数值实例采用 `M=256,N=384,K=640`、BF16 输入/输出、FP32 累加、四核。能力输入为 L0C/L0A/L0B 各 64 KiB，L1 为 256 KiB，L2 为 8 MiB；同一单位下 H=2、L=6、全设备计算吞吐 C=32。对齐、搜索阈值与步数上限使用 [具体策略参数](../../tiling-selection.md#8-基础双侧流式策略参数配置)。这些是受控贯穿例的模型输入，容量和性能量分别代入公式；它们不表示某款设备的实际规格，也不表示该设备 Host 对此 shape 的自然选择。

1. A/B 输入总量小于 L2，reusePressure=1；按 [公共参数派生](../../tiling-selection.md#7-基础双侧流式策略的参数派生) 得 rawEdge≈0.168229，初始探测块为 256×64，q≈0.019531，因此使用计算受限候选的对齐规则：M 步长 16、N 步长 32。
2. L1 对 K 内轴最低粒度的约束给出 M/N 上界均为 128。初始候选 128×128 的 q=1/64，尾轮均衡率为 1；其他候选 q 更大且均衡率不超过 1，故保留 128×128。
3. L0 双槽容量给出 KL0=128；L1 容量步数为 `262144/(2*256*128*2)=2`，小于步数上限 4，得到 KL1=256。
4. 两份累加块需要 128 KiB，大于本例 L0C 容量，选择单槽结果单元交接。L1 两阶段分别从 0、128 KiB 开始，各自容纳 A/B。
5. SWAT 尾轮沿 M 二分，最终八个任务，见 §11。每核首任务的 L1 窗口为 128、128、256、128，后续任务为 256、256、128；均执行五次 MMAD。A/B/C 总字节小于 L2，缓存 hint 保持默认。

### 9.2 整体流程

1. 确认正 M/N/K、Tin/Tacc 类型组合、Tout 输出契约、A/B 按选定轴顺序连续存储、C 固定 [M,N]。
2. 读取目标容量、布局对齐、搬运/MMAD/输出通路 能力。
3. 采用 DAG 的槽数、同步协议及真实分配边界。
4. 按 §9.1 评价 M/N 候选的容量、计算访存比与尾轮均衡率。
5. 选择 KL0，检查 L0A/B 双槽容量及输入连续轴对齐。
6. 按双侧流式可用 L1 总量计算 KL1，再检查各槽和总预留。
7. 若无合法组合则报告本模板无候选；否则保留完整配置。
8. 按 Kernel §3.2.8 选择类型/转置/尾部处理分支。
9. 校验有效范围、实际操作范围均落在相应合法存储内。
10. 校验每槽容量、总地址范围、bank 候选排布、尾部合法性。
11. 一起推导任务映射、launch 核数和每任务有效尺寸。
12. 保留默认 cache hint，记录有依据的遍历/缓存策略变更。
13. 输出实际消费者需要的参数，禁止生成无人使用的镜像参数。

## 10 切分后处理

### 10.1 UB 大小计算

不涉及。

### 10.2 Workspace 分配

不涉及。

### 10.3 TilingKey 设置

按 [总览 TilingKey 定义](../../template-overview.md#3-tilingkey)，将 A/B 的 ND、DN 分别绑定到独立编译期布局维度。Host 选择已注册的布局组合，Kernel 实例据此选择搬运和加载路径；M/N/K 与窗口大小等数值按实际消费者传递。

### 10.4 TilingData 设置

A/B 的 ND/DN 选择由 TilingKey 编译期维度承载，不再新增同义运行时标志。M/N/K、必要的张量步长、ML1/NL1/KL1/KL0、任务数等是推导信息，不要求全部新增为字段。复用实际后端 Params/TilingData，逐字段关联消费者并确认单位、边界、常量派生关系。

### 10.5 ScheduleMode 设置

执行图只有 Cube 路径，但工程任务类型仍采用目标实现所需设置；不能仅凭名称统一指定 MIX 或 AIC-only。

### 10.6 资源约束的输入与实例分配

目标容量、架构差异和参数来源统一引用 [npu-arch：硬件参数](../../../../../../../../ops/npu-arch/references/npu-hardware-params.md)；Host 获取方法引用 [npu-arch：Kernel/Tiling 侧获取](../../../../../../../../ops/npu-arch/references/npu-arch-guide.md#kerneltiling-侧获取推荐)。

本例取 `tileL1=(128,128,256)`、`tileL0=(128,128,128)`，采用单 L0C 协议。本例使用两个 128 KiB L1 阶段，分配如下：

| 资源 | 本例分配区间，单位 KiB | 容量条件 |
|---|---|---|
| L1 A 两槽 | [0,64)、[128,192) | 与 B 槽合计不超过可用 L1 |
| L1 B 两槽 | [64,128)、[192,256) | 每阶段 B 在同阶段 A 之后 |
| L0A 两槽 | [0,32)、[32,64) | 各槽与总跨度分别满足 L0A 约束 |
| L0B 两槽 | [0,32)、[32,64) | 各槽与总跨度分别满足 L0B 约束 |
| L0C 单槽 | [0,64) | 满足 L0C 可用空间约束 |

这些区间是 §9.1 假设容量下的分配结果。实际目标按平台容量与所选分区策略重新生成槽基址，不能将表中偏移直接复制到设备；等分实现见 [缓冲地址绑定](../../execution-strategies.md#6-等分容量分区)。数据需求量、分区预留量和设备容量分别核算。

KL1=256 由 §9.1 的 L1 总量与双槽公式得到；容量或布局输入变化后重新计算。

## 11 切分策略产出校验

贯穿实例得到两个 M 块、三个 N 块，共六个父任务；尾轮沿 M 二分，最终任务数为八。所选 SWAT 只有一个 M 调度窗口，最终执行表如下：

| 核 | 第一轮 taskId / 起点 / 有效尺寸 | 第二轮 taskId / 起点 / 有效尺寸 |
|---|---|---|
| 0 | 0 / (0,0) / 128×128 | 4 / (0,256) / 64×128 |
| 1 | 1 / (128,0) / 128×128 | 5 / (64,256) / 64×128 |
| 2 | 2 / (0,128) / 128×128 | 6 / (128,256) / 64×128 |
| 3 | 3 / (128,128) / 128×128 | 7 / (192,256) / 64×128 |

八个任务恰好覆盖输出；每个任务均完成 K=640。第二轮全部核继续执行，L1/L0 槽号跨任务推进，L0C 复用等待上一输出完成。固定槽容量按第一轮最大块保留。

SWAT 映射验证检查多个 M 组、奇数组 N 反向与最后合并组，例如 M 块数 9、N 块数 3、常规组宽 4 时组宽为 4、5。另检查边缘再均衡和尾轮分派，所有有效输出恰好覆盖一次。数值与地址校验见 [Kernel 校验](kernel-template.md#10-kernel-产出校验)。

生成算子时，不能只复算最终 tile 的容量。按 [公共选块校验](../../tiling-selection.md#6-校验) 用独立计算核对所选策略的候选、评分和任务结果，再与 Host 实际 TilingData 比较；若拟采用固定 tile、面积优先或其他新选择规则，必须先更新 [Contraction 公共选块策略](../../tiling-selection.md#11-策略绑定与实现对应) 及本模板的适用映射与实例，完成相应校验后再由算子引用，不能仅在算子设计中标为替代策略。本例的 128×128 是给定模型输入的推导结果，不是所有 BF16 或 FP16 输入的默认 tile。
## 12 Bias[N] 组合扩展的分派与切分

原贯穿实例保持 hasBias=false；以下为同一形状接入 Bias[N] 组合扩展。共享向量按最终子任务 nTaskOffset 取列区域，M 拆分仍为每个输出行广播同一 N 切片。

hasBias 参与编译期 TilingKey 分派；Bias[N] 地址、N 方向 stride、槽基址与跨度由现有 Params 承接。按当前输出列块的物理跨度预留。目标布局和容量仍须逐层验证。

本核每个有效输出子块独立首段注入；不能把每核首任务与每个输出首 K 段混淆。
