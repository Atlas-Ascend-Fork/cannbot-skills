# Contraction 选块

选块确定在给定输入、数值契约与目标能力下的一套可执行配置。配置包括分层块尺寸、物理布局、槽数、任务调度和结果交接方式；这些选择共同影响容量、搬运量和执行时间。

本页维护候选生成、成本评价与搜索规则。[公共契约](common-contract.md) 维护正确性不变量，[预处理](tiling-preprocess.md) 提供归一化输入，各模板提供执行组织和贯穿实例。

## 1 输入与产出

| 输入 | 必须明确的内容 |
|---|---|
| 问题 | 逻辑尺寸、真实 stride、输入/累加/输出类型、数值约束 |
| 能力 | 各层容量、合法布局与对齐、支持的搬运和计算形状；来自既有硬件与接口事实源 |
| 模板 | 任务范围、复用域、循环、各阶段数据角色和所有权交接 |
| 调度 | 给定候选时，生成每核实际任务及有效尺寸的确定算法 |
| 执行策略 | 槽分配、首块窗口序列、结果交接等已定义策略及其适用条件 |
| 评价策略 | 优化目标、成本公式、模型参数、枚举顺序、剪枝规则及同分处理 |

产出为完整候选及其推导：各层尺寸与槽跨度、真实窗口序列、每核任务、地址所需参数、成本分解和选择依据。复用工程现有参数载体；可派生的中间量不要求新增运行时字段。

### 1.1 策略绑定与实现对应

基础双侧流式模板在 §5、§7、§8 定义了具体的候选比较、参数派生和配置；其他模板按各自执行组织引用 §2–§4 的公共流程。生成某个算子时，先确认所选模板和策略的适用条件，再在既有设计产物中记录：策略引用、目标能力及模型参数的来源、dtype 专属合法性条件、候选的淘汰原因与评分、同分规则，以及最终分块、槽数和任务分布。候选输出必须能从这些输入独立复算，并与 Host 实际选择对应。

本页是 Contraction 选块策略的公共事实源。现有策略不适用时，先在本页定义或修改新策略，写清适用条件、输入及来源、候选生成与合法性、比较/同分/剪枝规则、任务分布、输出参数及独立校验方法，并同步对应模板的映射和实例；然后由算子设计和 Host 引用。只在算子设计中把固定 tile 或面积优先标为“替代策略”，不能视为已定义或已执行 Contraction 策略，更不能冒充 §5 的计算访存与均衡联合选块。固定值若来自硬件约束，应进入合法候选集；若用于优化选择，则必须由范式中已定义的策略推导。dtype 的存储、布局或数值约束可以改变合法候选集，不能仅凭 dtype 名称静默跳过候选评价。资源合法性、选择确定性和性能充分性分别验证；缺少模型输入或性能对照时，保留未验证边界。

## 2 候选生成与合法性

1. 根据形状、轴顺序及目标对齐计算每层合法尺寸集合。候选上界同时受输入槽、累加槽和模板复用域约束。
2. 联合选择块尺寸、槽数和输出交接策略。增加槽数可能缩小单块可用空间，不能先固定最大块再无条件开启双缓冲。
3. 用实际布局跨度核算每个独立分配区间；将 padding、槽间隔和驻留数据计入对应存储层。
4. 由调度算法生成最终任务及边缘有效尺寸，再展开各任务的数据窗口。启动窗口拆分等执行策略在此生效。
5. 校验完整输出覆盖、K 配对、实际读写范围和资源生命周期。非法候选在评分前剔除。

在已确认的测试尺寸限制内，逐池按实际发射核数、SWAT 展开的有效任务、真实 K 窗口序列、槽深及游标推进规则派生同核同槽再次使用的可达实例。空任务不计作访问；整块累加槽按输出任务推进，输入槽按其窗口推进，不能混用计数。`T>P` 只说明存在多轮任务，不保证超过槽深；游标在 launch 起点重置时，多次 launch 不能合计成同一次回绕；多 K 的 L1/L0 回绕也不代替累加槽跨输出任务回绕。

覆盖输入须实际触发所声明的复用路径，核对方法见 [Basic 最小验证](templates/basic/kernel-template.md#102-调度与边界校验) 与所选 adapter。尺寸限制不足以触发时，按本页既有候选、合法性与成本规则正常重新评价选择；仍无法满足则返回设计，记录具体池、计数及证据缺口。不擅自扩大尺寸、覆盖 Host 核数政策、退化槽深或虚构观测；可达性复算不替代实际分配、完成依赖和设备 Golden。

分层搜索可以先求 M/N，再求 K 和槽数，但后续约束失败时必须回退；分层次序不免除联合合法性检查。广播减少 GM 存储量，不自动减少计算任务或物理槽数。

## 3 工作量与成本模型

### 3.1 分层工作量

按最终任务和实际执行窗口统计，而非只用整个矩阵的尺寸：

| 成本 | 计算方式 |
|---|---|
| 有效计算量 | 对各输出区域求和 `2*mValid*nValid*K` |
| 实际计算量 | 按计算操作实际访问范围求和，计入对齐或合并计算产生的额外结果 |
| 各层搬运量 | 累计该通路每次传输的物理字节；驻留输入仅在其复用域入口计入 |
| 指令与控制开销 | 窗口数、搬运/计算发射数、事件交接和任务切换次数 |
| 缓存访问 | 基于任务顺序计算访问范围和重访距离；缓存命中率需由模型输入给出 |
| 空间占用 | 各层独立分配的峰值字节，按公共资源契约核算 |

例如尾轮将一个输出块沿 M 二分后，两任务各读完整 B 列块。总有效计算量不变，但 B 搬运与发射次数可能增加。输入在 L1 驻留时，跨任务复用必须依照实际驻留身份计数；不能把每个任务都按完整 GM 搬入收费。

### 3.2 计算访存指标的适用范围

对双侧流式、没有额外计算的一个 `m×n` 输出块，完整 K 的有效计算量为 `2*m*n*K`，GM 输入逻辑字节为 `eA*m*K+eB*K*n`。因此输入字节/计算量为：

`eA/(2*n) + eB/(2*m)`。

当 eA=eB=e 时，该指标与 `q=1/m+1/n` 成正比。q 只概括这一输入搬运模型，不包含输出、padding、缓存命中、启动或负载不均衡。

若 B 在同核复用域内被 J 个相同输出块复用，平均每块输入字节改为 `eA*m*K+eB*K*n/J`；此时必须使用新的成本公式。J 来自任务与驻留范围，不能仅由 N/M 块数推定。

### 3.3 流水完成时间

已给出阶段时长时，对每次操作 v 使用：

`start(v)=max(所有依赖操作的完成时间, 所需执行资源可用时间)`，

`finish(v)=start(v)+duration(v)`。

依赖同时包含数据就绪、槽可复用和同执行资源排队。按此展开启动、稳态及收尾。`max(搬运时间,计算时间)` 仅可作为满足重叠假设时的近似，不能省略首块启动或把有依赖的阶段强行并行。

阶段时长由传输字节、有效带宽、计算吞吐与发射开销估算；模型参数由目标能力或校准数据提供。多个核共享带宽时使用一致的共享资源模型，不能让每个核都独占设备总带宽。

### 3.4 多核负载

先按选定调度分配最终任务，再计算各核完成时间。以整个算子的完成时间为目标时，比较最晚完成的核及公共收尾操作。

`balanceRate=总有效工作量/(核数*最大单核工作量)` 适用于单元工作耗时一致的简化模型。尾轮拆分、驻留预载、非等尺寸任务或不同搬运成本存在时，应改用每核时间模型；仅统计任务数不足以衡量均衡程度。

## 4 搜索与确定性

公共流程允许不同的具体评价策略，但每次选择必须使用一套完整、确定的规则：

1. 固定合法候选顺序和模型输入。
2. 对候选执行 §2 的合法性检查。
3. 计算该策略规定的评分，并保留成本分解。
4. 根据该策略的严格比较、同分规则及容差更新最优候选。
5. 达到明确的终止条件后返回候选；没有合法候选则返回不可行原因。

容量越界、覆盖错误等属于确定淘汰。只有能证明某候选的最优下界仍不优于当前结果时，才可称为保优剪枝。启发式跳过或搜索预算截断必须属于具体策略定义；不能同时声称获得全局最优解。

改变成本模型、候选顺序、容差或同分处理都可能改变选块结果。需要还原某套实现的选择行为时，这些输入必须保持一致，不能只保留近似的评分公式。

## 5 双侧流式的计算访存与均衡联合策略

本策略用于基础模板的 M/N 候选比较。候选集合、枚举步长、初始候选、计算受限阈值 `computeBoundEdge`、剪枝均衡阈值 `balancePruneThreshold` 和比较容差 `scoreTolerance` 均须在搜索开始前绑定。硬件规格及其派生阈值由能力与成本模型提供，不在模板中维护固定芯片数值。

候选按 M 从大到小、N 从大到小枚举。令 `q=1/m+1/n`，b 为包含所选尾轮处理的均衡率；正尺寸有效候选必须有 b>0。

```text
best = initial_candidate
edge = computeBoundEdge
for candidate in candidates_in_descending_m_n_order:
    if not is_legal(candidate):
        continue
    q, b = evaluate_compute_memory_and_balance(candidate)
    if best.balance >= balancePruneThreshold and q > best.q and q > edge and edge > 0:
        continue
    compute_better = q <= edge and b > best.balance
    score_better = q / b < best.q / best.balance
    tied_better = abs(q / b - best.q / best.balance) < scoreTolerance and b > best.balance
    if compute_better or score_better or tied_better:
        best = candidate
        best.q, best.balance = q, b
        if compute_better:
            edge = q
```

该剪枝是此具体策略的启发式规则。相同评分及均衡率时保留先遇到的候选；计算受限阈值会随上述更新收紧，因此枚举顺序属于算法的一部分。不同类型还需要专属候选约束时，由类型能力绑定后进入合法性判断。

M/N 选定后，在相应槽数和输入布局下求合法 KL0，再按双侧流式的 L1 可用总量求共同 K 深度。实际布局无需额外 padding、A/B 元素宽度相等且各占两槽时：

`kSteps=floor(l1AvailableBytes/(2*(ML1+NL1)*KL0*inputElemBytes))`，`KL1=kSteps*KL0`。

实际窗口长度由执行策略生成，并裁剪到剩余 K。KL1 是分块上限，不保证每轮搬运长度相同。L0C 槽数、首块窗口拆分及槽基址发生变化后，重新检查相应资源和成本；不能从 q 的排序推断这些变化没有影响。

## 6 校验

资源校验覆盖边界容量、padding、单槽变双槽及驻留范围变化。成本校验分别比较有效计算与实际计算、一次搬运与重复搬运、常规任务与尾轮任务。用小尺寸枚举检查每核工作量和关键路径。

确定性校验覆盖同分、容差边界、候选顺序与动态阈值更新；用更小的候选集合穷举检查启发式搜索的结果及其局限。性能对照将预测成本与实测分别记录，并绑定相同输入、执行策略、目标和构建配置。

实现一致性校验使用独立于 Host 选择代码的计算，对同一输入、能力和策略参数复算候选合法性、评分与最终分块；至少覆盖不同任务并行度、尾块、dtype 专属资源边界以及容量合法但评分较差的候选。再核对 Host 返回的分块/槽数、SWAT 最终任务和 Kernel 消费字段。新增或修订策略先在本页及对应模板明确规则并验证，再供算子实现引用；不能凭算子侧的策略标签或原策略的示例、功能通过记录，代替新策略的选择校验与性能对照。

## 7 基础双侧流式策略的参数派生

本节限定正尺寸单矩阵、等宽输入、直接输出与双侧流式执行。使用 §5 的确定比较算法；下列模型量由目标能力与策略配置提供，均在搜索前固定。

| 参数组 | 内容 |
|---|---|
| 资源 | P 个核、L1/L0A/L0B/L0C 字节容量、L2 字节容量 |
| 性能 | H 为共享外存带宽、L 为共享 L2 带宽、C 为该输入类型的全设备计算吞吐；单位一致 |
| 对齐 | g 为基础分块对齐、aMem/aCompute 为内轴字节对齐、aOutput 为输出策略字节对齐、aK 为 K 内轴搬运字节对齐 |
| 搜索 | mSeedCap 为初始 M 上限、edgeRatio 为阈值收紧系数、minTailArea 为尾轮收益判断面积，以及 §5 的剪枝阈值与容差 |

### 7.1 性能分类与对齐

令 e 为输入字节数、a 为累加字节数，`reusePressure=max((M+N)*K*e/L2Bytes,1)`，`shapeRatio=(M+N)/(M*N)`。

`rawEdge=L/C + reusePressure*(1-L/H)*shapeRatio - (1+L/H)/K`。

先取 `mProbe=min(align_up(M,g),mSeedCap)`，`nProbe=max(g,min(align_up(N,g),align_down(L0CBytes/(a*mProbe),g)))`。若 `1/mProbe+1/nProbe>rawEdge`，归入访存受限候选集。

内轴字节对齐取 aMem 或 aCompute。M 候选步长在 A 转置时取该字节对齐/e，否则取 g。若 `K<M*N*H/((M+N)*L)`，N 步长取 aOutput/e；否则 B 转置取 g，B 不转置取内轴字节对齐/e。上述分类阈值用于本策略，不是容量合法性的替代条件。

### 7.2 候选上界与初态

设 `kAligned=align_up(K,g)`。最小 K 长度在访存受限时取 g，否则取配置的最小计算 K 字节数/e，并截到 kAligned。每轴上界依次受以下条件限制：

- L0C 至少容纳该轴长度与另一轴 g 的乘积。
- L0 输入双槽可容纳该轴与最小 K 长度；L0A/B 能力分别核验。
- L1 能容纳两侧双槽与所需 K 内轴粒度。
- 不超过输入形状对齐后的长度，按该轴候选步长向下对齐；输入短于步长时按 g 对齐处理。

等容量 L0A/B、对称预留的实例中，上界可写为：

`axisMax=min(L0CBytes/(a*g), L0ABytes/(2*minK*e), L1Bytes/(4*e*min(kInnerAlign,kAligned)))`，

再应用形状及轴步长约束。不满足对称前提时分别求两侧约束。

初始 M 取 `max(g,min(mMax,mSeedCap))`；初始 N 取 `max(g,min(nMax,align_down(L0CBytes/(a*M0),nStep)))`。初始化评分与均衡率，并置 `computeBoundEdge=rawEdge*edgeRatio`。随后按 §5 下降枚举，N 上限还受当前 M 的累加容量限制。所有除法需定义取整，尺寸计算使用整数。

### 7.3 尾轮均衡估计

候选 m/n 的原任务数 `T=ceil_div(M,m)*ceil_div(N,n)`。令 `R=ceil_div(T,P)-1`，`S=floor(P/(T-R*P))`。计算面积时，M 或 N 不超过 g 的轴使用实际长度替代对应候选长度，记结果为 `mEff/nEff`。

若 R=0，或 `floor(mEff*nEff/S)<minTailArea`，取 `tailRound=1`。否则令 `u=floor(sqrt(S))`、`v=floor((S-u*u)/u)+1`，取 `tailRound=1/(u*(u+v-1))`。

`balanceRate=(M*N/P)/((R+tailRound)*mEff*nEff)`。

这是选块阶段的尾轮耗时近似，实际拆分仍由 SWAT 的任务规则计算。两者不能共用一个含糊的“拆分数”：评分中的 S 是可用份数估计，执行中的 mTailParts/nTailParts 还受输入布局与搬运粒度约束。

### 7.4 KL0、KL1、槽数及任务参数

1. 选中 m/n 后截到形状对齐范围。本节等容量 L0A/B、相同元素字节数与双槽配置下，令 `kMax=floor(L0ABytes/(2*e*max(m,n)))`。若容量不同，分别取 `kA=floor(L0ABytes/(2*e*m))`、`kB=floor(L0BBytes/(2*e*n))`，以 `min(kA,kB)` 为容量上界；m/n 使用物理对齐长度，并按实际布局跨度和 K 对齐进一步筛选。K 对齐长度不超过 kMax 时直接采用该长度。
2. 否则 A 转置且 B 不转置时，KL0 按 g 向下对齐；其他方向优先按 aK/e 向下对齐，达不到该字节粒度时从策略绑定的下降 K 候选表中取首个不超过 kMax 的值。
3. 基础路径令 ML1=ML0=m、NL1=NL0=n，L1 输入阶段数为 2；用 §5 公式得到容量步数后，取 `kSteps=min(capacitySteps,maxKSteps)`，再得共同 KL1；maxKSteps 是具体策略绑定的发射步数上限。首块真实窗口序列由 [首块二分](execution-strategies.md#1-首块-l1-窗口二分) 生成。
4. 按 [L0C 选择](execution-strategies.md#4-l0c-选择与结果交接) 确定累加槽数和交接方式；片上槽起点使用实际分区跨度。
5. 令 Pused=min(P,T)。基础尾轮份数按 §9 选择，再由 SWAT 归一化并映射，任务数和发射核数与其一致。无边缘再均衡时两轴边缘区各为一个块。

输出字段由消费者确定：分块与槽数供计算块使用，任务尺寸及尾轮参数供调度使用，真实 stride 供地址使用，缓存 hint 供相应 GM 访问使用。缓存策略使用下述独立规则，不从计算访存评分自行推导 bypass。

### 7.5 缓存选择

本策略默认使用缓存。若 A/B/C 总物理字节小于目标 L2 容量，保持默认值。否则分别评估 A/B：A 在 N 方向仅有一个常规块且没有 N 尾轮再拆分时，满足一次消费条件；B 对称检查 M。只有原矩阵内轴字节长度与实际搬运窗口内轴字节长度均满足 cacheLineAlign 时，对应输入才选择 bypass。A/B 独立组合为默认、仅 A、仅 B 或两侧 bypass。

判断使用最终分块和尾轮份数；首块二分不改变 Host 的名义 KL1 字段。对其他缓存策略，必须明确采用另一套完整规则，不能混入本策略的评分过程。

## 8 基础双侧流式策略参数配置

以下配置与 §7 的候选、比较、剪枝及参数派生共同构成完整策略；它不是所有模板的默认参数，也不代表目标硬件容量。

| 公共量 | 配置值 |
|---|---|
| g、mSeedCap | 16、256 元素 |
| aMem、aCompute、aOutput | 128、64、256 字节 |
| aK、最小计算 K 字节 | 256、128 字节 |
| K 内轴最低粒度 | 访存受限单矩阵取 256 字节，否则 512 字节；A 转置且 B 不转置取 16 元素 |
| edgeRatio、balancePruneThreshold、scoreTolerance | 0.85、0.9、1e-9 |
| minTailArea | 4096 元素 |
| 下降 KL0 候选 | 128、64、32、16 元素 |
| maxKSteps、kMoveAlign | 4、16 元素 |
| cacheLineAlign、尾轮搬运阈值 | 128 字节 |
| L1 阶段数 | 双侧流式为 2 |

H/L 使用平台外存与 L2 带宽，计算吞吐按输入类型匹配；平台频率及带宽的获取引用现有硬件知识。L1/L0 分区基址与跨度取实际目标分配，两阶段 L1 的 A/B 在同阶段连续布置。


## 9 尾轮拆分份数选择

本节是基础双侧流式与 Batch 分块配置共用的确定策略。单矩阵取 `T=matrixTaskCount`，Batch 取 `T=batchCount*matrixTaskCount`，均以完整任务集合判断尾轮。输入为正整数 T/P/ML0/NL0、A/B 转置标志、inputElemBytes 和正的搬运粒度阈值；输出请求拆分份数，随后交给 [SWAT 尾轮分派](swat-scheduler.md#4-尾轮分派与拆分) 归一化并生成任务。

设原父任务数 T、核数 P。仅当 `T>P` 时取 `r=T%P`，否则 r=0。先置 `mTailParts=nTailParts=1`；r=0 时结束。令 `mSplitMinBytes/nSplitMinBytes` 为该输入布局下维持搬运粒度的策略阈值：

```text
while (mTailParts + 1) * nTailParts * r <= P and
      (not transA or ceil_div(ML0,mTailParts) * inputElemBytes > mSplitMinBytes):
    mTailParts += 1
    if mTailParts * (nTailParts + 1) * r <= P and
       (transB or ceil_div(NL0,nTailParts) * inputElemBytes > nSplitMinBytes):
        nTailParts += 1
```

M 优先尝试，N 的尝试发生在一次 M 拆分增加之后；不能替换成两个独立优化循环。阈值由策略输入提供，实际地址合法性仍需单独检查。


评分阶段的尾轮估计不替代本节请求份数，归一化后的实际份数不回写成另一套隐式搜索。验证零余数、少于一轮、双轴请求及阈值边界；份数归一化与输出覆盖由 SWAT 验收。
