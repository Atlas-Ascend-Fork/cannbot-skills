## 2 Kernel 模板分类

### 2.1 执行条件与实现组织

Contraction 语义由公共契约中的指标映射确定。随后依据资源、复用范围和任务组织选择执行模板；下表描述计算组织，不定义算子语义类别。

| 模板 | 选择条件与完整执行单元 | 文档 |
|---|---|---|
| 基础（SWAT） | 双侧按 K 窗口流式搬运，一个 M/N 输出块完成完整 K；尾轮重新切分为可选调度策略 | [DAG](templates/basic/dag-buffers.md)、[Tiling](templates/basic/tiling.md)、[Kernel](templates/basic/kernel-template.md) |
| 单侧 L1 驻留 | 整份 A 或 B 与另一侧流式窗口共同容纳；跨任务复用足以抵偿每核预载，任务按条带组织 | [DAG](templates/l1-resident/dag-buffers.md)、[Tiling](templates/l1-resident/tiling.md)、[Kernel](templates/l1-resident/kernel-template.md) |
| 保留轴分块（Batch 模板） | 保留每个输入自身的坐标映射，按保留轴坐标与 M/N 块分派；输入矩阵不要求完整放入 L1 | [DAG](templates/batch/dag-buffers.md)、[Tiling](templates/batch/tiling.md)、[Kernel](templates/batch/kernel-template.md) |
| IterBatch | L1/L0 各自组织一组保留轴坐标，逐坐标独立乘加；按实际父矩阵 pitch 核算活动容量 | [DAG](templates/iterbatch/dag-buffers.md)、[Tiling](templates/iterbatch/tiling.md)、[Kernel](templates/iterbatch/kernel-template.md) |
| MergeBatch | 合并多个保留轴坐标对应的 M/N 计算空间，计算扩大矩阵后只写各坐标对应的输出区域；同时评价扩大 L0C 和额外计算成本 | [DAG](templates/mergebatch/dag-buffers.md)、[Tiling](templates/mergebatch/tiling.md)、[Kernel](templates/mergebatch/kernel-template.md) |

类型与模板选择分开：各类型按输入、累加、输出契约和目标能力绑定。目标代码是否能表达某类型、布局或通路，由 [所选编程接口映射](../patterns.md#编程接口选择) 核对，不从模板名称推断。

### 2.2 公共约束归属

所有模板（包括基础模板）使用 [Contraction 公共契约](common-contract.md)。术语、预处理、资源/所有权不变量、硬件事实与语言映射的职责划分以该文件的归属表为准。公共规则不复制到每份模板；各模板写自己的输入条件、槽数、生命周期、地址实例和验证条件。

### 2.3 选择顺序与组合关系

选块遵循 [公共选块流程](tiling-selection.md)，使用各模板的搬运量、复用域、调度与流水模型；具体策略固定候选顺序、评分、剪枝和同分规则。SWAT 是任务调度算法，选块调用它计算任务分配及尾轮成本。

1. 先依据 [预处理](tiling-preprocess.md) 得到指标映射与真实存储。保留轴分块承接规则的 stride/广播映射；选 IterBatch/MergeBatch 前另证坐标组织和物理布局满足条件。
2. 再决定输入复用范围和输出任务。整矩阵驻留、保留轴坐标分组或合并各自改变资源模型，不能只替换一个 Kernel 名而沿用原 Tiling。
3. 使用所选调度算法（如 [SWAT](swat-scheduler.md)），在候选输出任务上评估尾轮重新切分，替换父任务而不叠加执行。不同子任务仍各自完成完整 K。
4. 将槽数、流水协议与块尺寸联合检查，不满足资源或成本条件时回退候选；具体语言承接最终确定的策略。

| 组合 | 成立条件 |
|---|---|
| 单侧驻留 + 尾块重新切分 | 拆分后每个核的驻留副本和复用域重新核算；任务条带内的输出块与调度子任务不能混为一谈 |
| 保留轴分块 + 尾块重新切分 | 子任务保留父任务的保留轴坐标和每个输入的地址映射；在对应 M/N 区域内完成覆盖证明 |
| 保留轴分块 + 单侧驻留 | 驻留输入矩阵身份在复用域内不变；广播只表示可能的复用机会，必须按实际坐标映射验证 |
| IterBatch / MergeBatch | 二者是不同的保留轴坐标计算组织，不能把坐标组参数直接互换；只有另外设计完整资源及地址映射后才能嵌套 |
| 任意模板 + L0C 双缓冲 | 两槽容量成立，每槽独立按完整 K 与输出完成交接；同步及结果交接参数随实际接口绑定 |

表中是组合的证明条件，不表示具体源码已经注册全部组合。跨 K 分工涉及部分和合并，另需完整设计，不能借用尾块重新切分的“独立输出”协议。

### 2.4 执行机制与维护位置

模板按任务组织、驻留范围和计算循环选择；附加输入的消费者与交接规则见 [公共契约](common-contract.md#6-附加输入与输出交接)。

| 执行机制 | 维护位置 |
|---|---|
| 首块窗口二分、L1 成对分区、L0C 槽数与交接 | [公共执行策略](execution-strategies.md)；模板只给选择及实例 |
| 当前任务A/B完整K面板同时驻留 | [驻留DAG变体](templates/l1-resident/dag-buffers.md#3-双侧完整-k-面板驻留变体)及其Tiling/Kernel；不混同单侧全局矩阵跨任务驻留 |
| 输入描述的K窗口跨多个payload窗口 | [双层窗口策略](execution-strategies.md#7-双层-k-窗口与附加输入)；附加输入的编码与组粒度由实际公开契约提供 |
| 最终输出消费系数，资源最后消费者改变 | [公共交接机制](common-contract.md#61-附加输入的资源交接)，具体输出参数仍归接口映射 |
| 保留轴与矩阵轴交错导致矩阵行stride改变 | [地址章节](templates/batch/kernel-template.md#11-batch-与矩阵轴交错存储) |

已有分块、单侧驻留、IterBatch等结构在量化算子中再次出现时，复用原模板；ReLU等后处理名称不构成新的contraction执行结构。新增变体先在已有目录明确差异，只有无法保持清楚职责时再拆出独立模板目录。

### 2.5 多个保留轴坐标的执行组织

矩阵形模板可沿一个或多个保留轴坐标分派独立输出矩阵；各输出坐标共享同一收缩定义，但输入可按各自 shape/stride 映射或明确的广播关系取数。Batch、IterBatch、MergeBatch 是三种执行组织模板名，不是 Contraction 的语义类别；各自保留独立目录及 DAG、Tiling、Kernel。它们仅描述坐标如何分块、驻留或合并。

| 执行模板与目录 | 任务及计算组织 | 主要适用条件 | 选择时计入的成本 |
|---|---|---|---|
| 保留轴分块（Batch 模板）：`templates/batch/` | 一个保留轴坐标的 M/N 输出块完成完整 K，输入按 K 窗口流式搬入 | 输入不必整矩阵装入 L1；输入坐标映射可由模板表达 | 输出块任务数、输入重访、窗口发射与尾轮负载 |
| 保留轴驻留迭代（IterBatch）：`templates/iterbatch/` | BatchL1 个保留轴坐标对应的完整矩阵成组驻留，L0 按 BatchL0 子组准备，每段 K 逐坐标计算 | 矩阵组及各层坐标子区满足容量、布局和搬运条件 | 完整矩阵装载、组内 MMAD 次数、矩阵间距、任务并行度和尾组空闲 |
| 保留轴矩阵合并（MergeBatch）：`templates/mergebatch/` | 将多个坐标对应的 A 沿 M、B 沿 N 拼接，计算扩大矩阵，只写各坐标匹配的输出块 | 扩大输入与结果布局合法，目标支持对应子块输出，额外计算成本可接受 | 扩大 M/N 的计算、L0C 占用、有效输出次数与尾组形状 |

各模板的三份文档入口见 §2.1。IterBatch 和 MergeBatch 不自动继承保留轴分块的全部地址映射能力：候选必须按各输入映射证明驻留数量、拼接地址和消费者一致。

#### 2.5.1 选择流程

1. 由同一归一化结果获得保留轴映射、M/N/K、输入方向和类型；筛选三个执行组织模板各自可表达的候选。
2. 各模板按自己的 Tiling 推导分块、任务、布局、槽数和交接协议；复用 [公共选块流程](tiling-selection.md)，使用本模板的工作量模型。
3. 比较合法候选的最慢核完成时间，计入首轮、稳态、尾组和输出。忽略 padding 时，合并 q 个等形矩阵产生 q² 个乘积块而只输出 q 个，MergeBatch 的计算量约为独立计算的 q 倍；减少 MMAD 发射次数需与这部分代价一起评价。
4. 将选择结果绑定到工程已有编译期模板分派和对应 Params；各路径保留自己的循环、物理布局、同步和指令发射顺序。复用已有 key/注册机制，不另建一份场景注册表或在内层循环反复判别模板。

#### 2.5.2 组织与性能验收

场景入口维护三者关系和选择流程；公共规则只由原事实源维护，各模板保留具体推导与贯穿实例。合并入口不要求合并 Kernel 骨架或缓冲协议。

分别验证路径内部和路径选择：前者固定模板及参数，核对生成实现并做同条件精度与性能对照；后者在相同输入上比较合法候选，检查选择结果。模型用于候选筛选，不预设三个模板的固定性能排序。实现身份和测量条件遵循 [公共验收](common-contract.md#51-实现身份与性能对照)。

## 3 TilingKey

### 3.1 TilingKey 定义

复用工程已有编译期分派机制定义场景、输入方向及确实改变代码的策略维度；dtype 使用工程注册的编译期类型，不再复制成 runtime key。具体注册宏及入口绑定由 [所选编程接口](../patterns.md#编程接口选择) 承接。

基础模板将 A、B 的 ND/DN 存储方向分别作为独立的 TilingKey 编译期维度，记为 `aLayout`、`bLayout`（语义名称，具体声明复用工程已有模板参数）。二者独立选择，共四种组合：

| aLayout | bLayout | A 连续存储轴顺序 | B 连续存储轴顺序 |
|---|---|---|---|
| ND | ND | [M,K] | [K,N] |
| ND | DN | [M,K] | [N,K] |
| DN | ND | [K,M] | [K,N] |
| DN | DN | [K,M] | [N,K] |

逻辑矩阵始终为 A(M,K)、B(K,N)。Host 从算子公开的存储方向契约选择对应 key；不能仅凭 shape 猜测方向。Kernel 以编译期布局参数选择 GM 步长解释、搬运与加载实现，不能只在 TilingData 中记录运行时转置标志而仍分派到同一个无布局区分的实例。连续输入的步长由 M/N/K 和所选方向推导；若工程已有转置模板参数，直接复用其与 ND/DN 的对应关系，不再增加同义字段。

该维度描述 A/B 的 GM 存储方向，不等于 L1/L0 的 NZ/ZN 物理格式，也不改变 C 的输出轴顺序契约。具体实现必须明确注册了四种组合中的哪些组合，未实现组合不能落到 ND/ND 默认分支。

此知识范式不分配跨算子的固定数字 key。生成具体工程时必须列出合法组合及其唯一入口；未支持组合不能落入默认成功分支。

`hasBias` 是 Elementwise/Broadcast Bias[N] 组合扩展在各执行模板中的可选编译期分派维度，优先复用工程已有参数。Host 按 Bias[N] 组合扩展是否存在选择有/无组合扩展实例；组合扩展输入只有 N 轴 shape/stride，广播到其余输出轴。无组合扩展实例消除 bias 地址、搬运、资源与同步代码；其他差异仅在改变编译实现时进入 key。

### 3.2 TilingKey与kernel模板对应关系

先绑定场景，再绑定 §2 中实际采用的实现模板；dtype、累加和数值策略只在确实改变编译实例或参数布局时进入 key。若公开接口已经区分多个算子，无需再用一个无效场景字段重复编码。只有实际消费字段进入 key。

## 4 TilingData

### 4.1 TilingData 定义

生成工程逐字段列出类型、单位、来源、消费者及值域：M/N/K、物理 stride、保留轴映射、L1/L0 块、buffer stage、tail 配置、launch 数及确实使用的附加输入窗口。组合扩展启用时列出 Bias[N] 的地址、N stride 与资源字段。复用选中 Kernel 的现有 Params，不为本文再新增镜像结构。

规范中的 usedCoreNum、mainTiles、mainCoreNum、ubSplitIdx、ubFactor、blockFactor 是自管 Vector 分核模型的公共字段。所选 Cube 实现路径的 UB 字段不涉及；launch 数映射到实际 host launch 接口，scheduler 自己计算有效任务。不得向第三方 Params 强塞这些字段。若增加自管 Vector 阶段，应为该阶段单独说明这些字段及其消费者。

### 4.2 TilingData与kernel模板对应关系

基础模板消费矩阵维度与分块；保留轴分块模板消费各输入坐标映射；驻留模板消费复用域与完整父布局；尾块模板消费父子任务映射；IterBatch/MergeBatch 消费各层坐标组织。附加输入的窗口及物理布局仅由实际消费它们的路径绑定。Bias[N] 组合扩展字段只由启用组合扩展的模板实例消费。每个模板引用其 Tiling 文档，不使用一个最大结构掩盖未初始化字段。

## 5 总结

先锁定语义和存储，再建模 buffer、分核及入口。公共预处理不承担 scheduler 切分；场景模板不重复 dtype 编码细节。

## 6 产出

### 6.1 产出结果

在已有设计产物中给出：模板清单、key → kernel 对应表、TilingData/Params 字段消费表和源码版本。

### 6.2 产出校验
