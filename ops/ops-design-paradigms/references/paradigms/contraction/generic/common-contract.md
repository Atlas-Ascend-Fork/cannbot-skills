## 1 语义与数值

Contraction 的内核是“输入按指标映射对齐、逐项相乘，并沿收缩指标求和”。一般形式为 `Y[o]=sum_{r∈R} A[phiA(o,r)]*B[phiB(o,r)]`：`o` 表示保留并写入输出的指标，`r` 表示被消去的收缩指标，`phiA/phiB` 描述各输入的逻辑坐标映射。实际 shape、stride 和允许的广播关系共同决定物理地址。矩阵形模板将输出轴记为 M/N、收缩轴记为 K；这是执行模板的坐标命名，不构成独立的算子语义类别。执行策略不能改变保留指标、输入指标配对或求和范围。

每个模板明确输出所有者：一个完整 K 的计算任务，或有明确部分和合并协议的一组任务。本目录基础、单侧驻留、尾块重新切分及保留轴坐标执行组织采用前一种；保留轴坐标决定输出位置，不参与收缩求和。

基础数值实例采用下表组合。其他类型由公开契约和目标能力确定。每次实例化同时确定输入解释、累加规则和输出转换，不由输入类型隐式推定输出类型。

| 组合 | 累加要求 | 输出与比较要求 |
|---|---|---|
| FP16 → FP32 | 按 FP16 输入值参与乘加；部分和以 FP32 保留 | Tout 及转换舍入由输出契约确定；与 Golden 按规定误差比较 |
| BF16 → FP32 | 按 BF16 输入值参与乘加；部分和以 FP32 保留 | Tout 及转换舍入由输出契约确定；与 Golden 按规定误差比较 |
| INT8 → INT32 | 有符号整数乘加，部分和以 INT32 保留 | Tout=INT32 时保持整数结果；其他输出类型按转换契约处理 |

浮点 Golden 先按 Tin 表示输入，再执行约定的参考计算和最终输出转换。不同 K 分段的舍入差异按误差契约判断；不能用实数公式要求默认逐位一致，也不能在每个 K 窗口提前转成 Tout。

整数 Golden 使用更宽整数计算。一个足以保证各中间部分和不溢出的条件是 `sum_k abs(A[m,k]*B[k,n]) <= 2^31-1`；仅检查最终和不足以排除中间溢出。若允许超出该范围，算子契约必须明确溢出规则，并由目标能力实现该规则。

## 2 存储与地址

输入归一化遵循 [预处理](tiling-preprocess.md#1-问题与设备信息)。逻辑坐标和物理布局分离，A/B 的 ND/DN 分发及 C 的输出轴顺序见 [总览](template-overview.md#3-tilingkey)。能力不足的具体实现不能默默按另一轴顺序读写。

GM 地址分解为“张量原始基址 + 当前保留/收缩指标坐标对应的物理偏移 + 当前输出任务偏移 + 窗口内偏移”。片上地址分解为“存储层分配基址 + 物理槽偏移 + 槽内数据布局偏移”；不能加入 GM 全局基址，也不能因切换任务而丢失片上槽轮转状态。

`LayoutX(coords)` 表示所选 X 物理布局的字节偏移；`SpanX(shape, dtype, layout)` 表示涵盖全部合法访问及 padding 的物理字节跨度。若某模板使用元素偏移函数，必须另行标明，并只乘一次元素字节数。源子窗口保留父布局的 stride；目的布局独立确定，不能按有效 shape 猜测物理 pitch。

对齐扩大必须同时证明 GM 访问合法和片上空间足够。K 方向补齐不能向有效结果引入非零额外贡献；结果仅按输出有效范围写回。局部窗口变小不等于固定槽跨度变小。输出空维与 K=0 的处理由预处理契约负责，正尺寸计算骨架不替代该处理。

### 2.1 NZ/ZN 布局坐标约定

本节统一模板实例中选用的 16×16 分形坐标函数；采用其他分形粒度时，从对应类型与接口布局重新推导。它是布局选择，不是全部硬件或数据类型的固有规格。令 `Ra=align_up(R,16)`、`Sa=align_up(S,16)`，偏移以元素计：

```text
NZ(i,j;R) = (j//16)*Ra*16 + i*16 + j%16
ZN(i,j;S) = (i//16)*Sa*16 + j*16 + i%16
physicalSpanElems = Ra*Sa
byteAddress = slotBaseBytes + elementOffset*elementBytes
```

NZ 对应轴序 `(j1,i1,i0,j0)`，ZN 对应 `(i1,j1,j0,i0)`；父窗口的 R/S 决定跨分形步长。子窗口读取保留父布局，目的重新构造局部布局。各模板只声明使用空间、父形状及局部坐标，再代入本节函数给出自己的数值表。接口表达见 [所选编程接口映射](../patterns.md#编程接口选择)。

## 3 资源描述

分别描述 UB、L1、L0A、L0B、L0C 及确实使用的其他存储：逻辑数据角色、独立物理槽份数、每槽物理跨度、槽内保留轴坐标子区、生产者、所有消费者、最后消费与可复用条件。一个物理槽包含多个坐标子区时，同时列出槽数和子区数，不能用其中一个替代另一个。

按每层实际分配区间核算峰值，`requiredBytes = sum(各独立分配槽跨度)`；共享槽只在证明生命周期不交叠后计一次。输入广播能减少 GM 存储，不自动减少 L1/L0 分配；有效数据量、物理分配量和传输量分别计算。槽间 padding 和保留 pitch 计入容量。

容量及能力来自 [硬件事实源](../../../../../../ops/npu-arch/references/npu-hardware-params.md)，取得方式见 [平台接口入口](../../../../../../ops/npu-arch/references/npu-arch-guide.md#kerneltiling-侧获取推荐)。模板写需求量和选择条件，不能把某芯片的容量、bank 数或专属通路作为范式定义。bank 分析以本模板并发访问集合和实际布局为输入；缓存 hint 以重访关系为输入，二者都不能代替正确性同步。

## 4 所有权与同步

同步作用域由物理资源的交接边界决定，不按操作条数机械设置。生产完成后消费者才能读取；所有消费者完成后下一生产者才能覆盖。资源仍由同一侧持有，不等于前序异步操作已经完成；计算顺序和同流水依赖仍由所选接口语义保证。

| 资源角色 | 发布条件 | 归还条件 |
|---|---|---|
| 输入窗口 | 当前窗口生产完成 | 该窗口的最后一次读取完成 |
| 驻留输入 | 整个驻留范围生产完成 | 复用域内所有任务的最后一次读取完成 |
| 计算输入槽 | 输入准备完成 | 使用该槽的最后一次乘加完成 |
| 完整 K 的累加槽 | 所有 K 段完成，结果就绪 | 输出侧完成该槽全部结果读取 |

整块输出方案中，累加槽在首次写入前取得可写权，由计算侧持有整个 K 归约，最终结果发布后才交给输出侧。数值初始化按当前输出任务的 K 起点决定；同步状态和初始化条件不是同一个概念。只有一段 K 时，该段同时初始化、完成并发布。

若目标支持结果单元交接，只有已完成完整 K 的单元能提前发布；发布、消费和复用范围必须一致。具体接口机制只表达这些依赖，不改变数值归约语义。两个输入槽就绪时间和最后消费者不同，则分别管理，不能强行共用一个提前释放的事件。

双缓冲需要两份空间及合法的生产/消费/复用顺序。甘特图声明时长假设、明确起止，并同时满足跨流水依赖和同流水资源约束；模板自行给出窗口及槽号。并行机制的具体表达见 [所选编程接口映射](../patterns.md#编程接口选择)。其他范式的存储分配约定只在其适用场景引用；本目录所选存储与同步方案由对应 adapter 绑定。

## 5 产出与验收

每个模板分别交付：输出覆盖映射、各层资源表、GM/片上地址公式、完整数值计算过程、所有权交接和实现字段消费者。例子中的逻辑枚举尺寸不自动成为硬件合法分块。

覆盖验证检查输出无遗漏、无重复、输入配对正确；地址验证包括转置、尾部、跨任务及槽回绕；数值验证包括多段 K、实际 Tin 表示和输出转换。变更模板后重新绑定本次源码、参数和输入 Golden。文档检查、编译、设备精度与性能各自提供证据，不互相替代。性能比较保持问题、数值契约和运行环境可比。

### 5.1 实现身份与性能对照

| 证据层 | 记录内容 | 能确定的范围 |
|---|---|---|
| Host 路由 | 注册函数、平台输入、key、原始 tiling 及结构版本 | Host 选择结果 |
| 运行时分派 | 实际 kernel 符号、key、launch 核数、运行时 tiling、关联的 profiler task | 实际发射的入口及参数 |
| 显式源码实例 | 源码与头文件哈希、模板参数、构建宏、编译器、生成对象及 ELF | 该编译实例的窗口、布局与同步策略 |
| 预编译包内部实现 | 可关联到产物的构建记录、源码身份或可解释的指令证据 | 包内执行分支；缺少对应证据时保留未知 |

四层分别记录，不以产品版本、key、符号名称或相同 tiling 互相替代。Tiling 结构版本变化时按字段和单位转换，不能直接将原始字节解释为另一个结构。对照还需绑定输入、Golden、输出类型、实际分区地址、缓存条件、预热与测量次数及有效设备独占范围。

性能归因在相同输入与配置下单独切换目标策略，并覆盖不同形状和跨任务槽复用。窗口二分可能缩短首次输入等待，也可能增加搬运和事件开销；结果交接方式改变并行机会，均不能据此推定固定收益。未定位的残差保留为残差，不按接口名称归因。污染计时整批作废，重新采集的数据与作废记录分开保存。

### 5.2 设计一致性与证据选择

模板中的任务枚举、地址表、槽号轮转和最后消费者检查，用于核对设计与实际实现是否一致。它们描述计算和安全约束，不自动新增取证接口、运行时事件输出或独立算子能力。实现单元按真实输入域和可交付行为划分；同一多块能力应同时承接其数值验证和资源、同步检查，不为逐槽取证单独增加必经实现单元。

| 原保证 | 设计与实现一致性检查 | 设备验证的职责 |
|---|---|---|
| 完整 K 归约与唯一输出覆盖 | 独立枚举任务和 K 区间，对照实际 Kernel 控制流及对应生成产物；核对尾轮替换父任务、累加目标与写回次数 | 用非恒定输入的多块、尾块、单段/多段 K Golden 区分漏算、错配和尾部错误；Golden 不单独证明写回唯一 |
| 合法地址与资源容量 | 核对真实布局、分配区间、对齐、padding、固定槽跨度及所有操作访问范围 | 对实际边界输入做 Golden，使用目标可提供的内存检查；数值通过不免除分配和地址证明 |
| 已选双缓冲、槽轮转与消费者完成后复用 | 检查真实独立存储、源码中的访问/别名/跨任务计数，以及生成产物中的生产就绪、最后读取完成和同槽再写入依赖 | 多块和重复调用 Golden 覆盖旧值污染；静态 depth、轮转枚举或 Host 计划不证明实际同步或重叠 |
| 首轮、收尾及资源生命周期 | 检查初始可写条件、最后有效输出、无任务分支、待完成操作及回收顺序 | 重复调用变更输入并逐次对照 Golden，形状变化限于已支持的输入域 |

源码和生成产物能证明的约束，通过已有设计约束/审查证据承接。例如已有 Unit 格式中的 `design_constraints.review_evidence` 或前置补证中的 `review_evidence`，分别填写真实 `artifact`、`check` 和 `pass_criteria`，关联本次编译实例；不将这些审查项机械复制为必须采集事件的测试义务。独立 Host 枚举可用于推导覆盖和选择测试输入，不能作为设备实际执行事件。

只有规格或已选契约确实要求运行时观察时，才建立相应观测义务，例如实测流水重叠或公开交接事件；它需要明确实际采集来源、范围及判据，不默认要求普通 MatMul 新增 GM trace 系统。只有接口声明、静态槽数或预期计划时不得宣布同步已证明；生成产物不能解释关键依赖时，记录缺失的访问、参与者或完成边界，返回对应设计/adapter 章节并阻断依赖该能力的后继。编译检查不代替设备 Golden，设备 Golden 也不代替设计一致性和性能证据。

## 6 附加输入与输出交接

附加输入按实际消费者归位：随 K 分组解释输入并参与乘加的数据属于计算输入依赖；仅在最终累加结果写出时消费的数据属于输出交接依赖。二者不得共用一个含糊的“附加输入生命周期”。后处理若不改变 contraction 的资源或交接，只作为边界契约，不搬入基础模板正文。

### 6.1 附加输入的资源交接

对于确实存在附加输入的实现，DAG 写出其生产者、存储层、消费者及最后消费；Tiling 计入真实槽跨度；Kernel 地址按其自身逻辑轴和物理布局计算。只以“附加输入”命名无法确定这些属性。

以输出通路消费 N 方向系数为例：本任务系数为 `S[nTaskOffset:nTaskOffset+nTaskValid]`，L1 中的系数槽由输入搬运生产、输出通路消费。因此复用依赖是“输出读取完成→下一次输入搬运”，不是 A/B 数据的“MTE1 读取完成→下一次输入搬运”。标量系数若直接绑定到操作参数，不虚构一份向量 L1 Buffer。广播系数按自己的映射确定身份；数据任务变化不必然意味着系数值变化。


按 K 消费的附加输入使用 [双层 K 窗口策略](execution-strategies.md#7-双层-k-窗口与附加输入)，其编码与组坐标由实际公开契约提供。

### 6.2 可选 bias 的语义与数值

`hasBias` 表示可选输入是否存在，不由其数值是否为零决定。无 bias 的编译实例保持原计算，不分配 bias 槽、不建立 bias 事件、不计算 bias 地址。提供全零 bias 仍属于有 bias 实例。

Contraction 核心只定义归约结果 `acc[o]=sum_{r∈R} A[phiA(o,r)]*B[phiB(o,r)]`。当前矩阵形模板通过 Elementwise/Broadcast 组合扩展表达 `A@B + bias`：bias 输入严格为一维 `[N]`，语义为 `Y[...,m,n]=convert_out(acc[...,m,n]+bias[n])`，即沿输出 N 轴逐元素相加，并广播到 M 轴及其他保留输出轴。组合扩展使用上述逐元素加法语义及 [Broadcast](../../broadcast/patterns.md) 坐标映射；本契约只规定它与 Contraction 模板的组合边界，不扩展到任意 bias shape 或逐保留轴坐标的 bias。

`hasBias` 仅表示是否装配该可选组合扩展。无组合扩展实例保持原收缩计算，不分配 Bias/L1 槽、不建立 bias 事件、不计算 bias 地址；全零向量仍属于组合扩展存在的实例。组合扩展必须沿每个有效输出的 N 坐标读取 `bias[n]` 并恰好应用一次，K 分窗、任务拆分和槽回绕不能改变次数。K=0 且输出非空时，收缩结果为零，组合扩展仍需产生 `convert_out(bias[n])`。

Bias[N] 的存储类型、参与运算类型、转换时机和舍入按组合扩展与公开输出契约绑定。若为减少中间写回而将组合扩展融合到首段累加初始化，逻辑结果仍须满足 `acc+bias[n]` 的契约及误差要求；融合路径不改变组合扩展的 Elementwise/Broadcast 语义。

验收覆盖有/无组合扩展、全零及非零 Bias[N]、不同任务 N 分块、多段 K、尾轮子块、槽回绕和 K=0。检查每个输出仅应用一次、N 起始偏移正确，且无组合扩展分支不访问 bias 地址。

## 7 设计与接口适配契约

本节复用已有设计产物和所选 Kernel 的 Params/TilingData 描述边界，不建立第二份运行时结构。通用层先明确能力要求，adapter 从对应目标 SDK、公开接口及硬件事实源核对支持条件；能力不足的候选不能进入最终选择，待确认的项保留验证义务。

| 通用层需要的能力事实 | 核对范围 |
|---|---|
| Tin/Tacc/Tout 组合 | 输入解释、累加、结果转换和舍入 |
