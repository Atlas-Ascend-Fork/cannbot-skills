## Step 6.0：★ 知识库卡检索（MUST）

优化选型前，经 `knowledge-query` 按**瓶颈 kernel 的模式 + 平台 310p** 检索 performance/precision runbook 卡（如 gather / DataCopy / scalar / pipeline / 流水比主题）：

1. 命中卡的替代模式/实测数字并入优化项清单（标注来源卡路径）
2. 卡中的**负结果**（某模式已证伪）直接排除对应优化方向，禁止重复试错
3. 未命中也要在优化项清单注明「已检索，无增量」

## Step 6.1：优化项排序（瓶颈归因驱动）

输入 = stage 5 的瓶颈分析（kernel_details 流水比 + 形态合规表 + m200 风险回归表）。按**预期收益 × 确定性**排序优化项：

| 排序依据 | 说明 |
|---------|------|
| 设备侧占比 | 瓶颈 kernel 占总耗时比例（占比小的不优先） |
| 瓶颈类型已知性 | 已有实证替代模式（如 E19 向量化）的优先于探索性的 |
| 结构性 vs 局部性 | 结构性问题（如 depthwise 走稠密 GEMM）单列，工作量评估入报告 |

产出：优化项清单（每项含目标 kernel、瓶颈类型、替代模式、预期收益档），在对话中展示。

## Step 6.2：单优化项循环（每个优化项独立迭代）

**每轮迭代固定四步，顺序不可交换**：

```
改（最小增量，一次只改一个假设）
  → 编（stage 3 构建路径）
  → 精度回归（stage 4 全套件 + 确定性——硬门，红则回退本轮改动）
  → 性能复测（stage 5 采集路径，device 整轮口径 + wall-clock 参照）
```

**纪律**：

1. **精度回归是每轮硬门**——任何一轮精度/确定性变红，本轮改动无条件回退（禁止带红迭代）
2. **独占设备**——所有精度/性能测量前 `npu-smi` 核实无同卡并发（U10）
3. **每轮落盘**：`perf/<op>/opt_iter_<NN>/` 存本轮 diff 摘要 + 精度结果 + 性能数字（可复现）
4. **迭代上限**：单优化项 ≤5 轮；**同一失败签名 ×3 轮 = 退役信号**——停止迭代，按退役信号纪律升级（换路线或报告 owner），禁止闷头继续
5. **形态约束不退化**：每轮验证三约束不回退（block_dim 不下降、已消除的标量环不得复现、cube 路径不回退 vector）

## Step 6.3：达标判定

| 判定 | 条件 |
|------|------|
| **达标** | owner 目标值达成（如几何平均加速比 ≥ 目标）且形态阈值全绿 |
| **上限收敛** | 优化项清单耗尽或连续两轮 geomean 改善 < 5%——停止，报告最终态与剩余差距归因 |
| **契约冲突** | 达标需要违反契约（如精度口径）→ 停止并升级 owner 裁决 |

## Step 6.4：优化报告

在 `perf/<op>/perf_report_<op>.md` 追加「优化历程」节：每轮迭代的改动/精度/性能数字表、最终态 vs stage 5 基线的对比、形态合规终态、剩余差距归因与后续建议。
