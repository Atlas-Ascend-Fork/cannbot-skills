# API 范围与规则路由

“完整生成”指为本次选定接口完成取证、资料对齐、审阅和最终化，不承诺已验证全部 AscendC API。当前检测器识别 `adv_api`、`basic_api`、`tensor_api`、`c_api`、`simt_api`，无法解析的形态必须报告能力边界，不补造原型。

API 类别取自实际代码位置；调用约定独立记录为 `__aicore__`、`__simd_callee__`、`__SIMT_DEVICE_FUNCTIONS_DECL__` 或未限定。不能仅凭类别名称推断执行模型，也不能将全部 API 都归入 SIMD。

| 目标代码特征 | 按需读取或核验 |
|---|---|
| 任意类别 | 精确原型、参数/返回值、产品与条件、用户可见约束和可验证示例 |
| 原型或直接相关类型实际出现 LocalTensor、GlobalTensor、TPosition | [Tensor 参数表述](tensor-parameters.md)；仅对涉及的参数或成员应用 |
| SIMD 声明或实现 | 当前成员涉及的寄存器、mask、状态及同步要求；没有对应对象或行为时不增加该项 |
| SIMT 声明或实现 | 当前成员实际暴露的线程、地址空间、同步及调用限制；不强加 Tensor、TPipe、Compute/Process 对象 |
| 确实需要架构背景帮助理解 | [架构资料使用范围](architecture-context.md)，只读取与当前事实有关的公开来源 |

对每个字段区分：已证实、不适用、尚未确认。不适用不算证据缺口，但覆盖表仍须引用已有 K-ID 并说明具体原因；尚未确认不能写成默认支持、默认限制或具体数值。是否读取 Tensor 参考由实际签名和类型决定，不由 `tensor_api` 目录名单独决定。

各类别共用取证与交付工具，差异规则在此按条件路由。只有新增的实际参考内容需要分组时再建目录，不为尚未维护的规则预建空目录。
