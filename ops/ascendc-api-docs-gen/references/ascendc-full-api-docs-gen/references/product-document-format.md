# 产品名称与产品标签规范

本规范适用于最终 Markdown 全文，覆盖功能、公式说明、约束、返回值说明和调用示例说明。产品名称及标签中的空格不得由通用中英文排版规则改写。自动名称替换仅作用于展示文字，保留代码块、行内代码、链接目标、引用链接定义和 HTML 属性原文；代码中的产品展示文本若需更新，须核实语义后单独编辑，不得改动接口常量或资源地址。

## 产品支持情况

最终文档第1章必须是 `## 产品支持情况`，使用下列无序列表，不使用 Markdown 或 HTML 表格。仅依据代码证据填写支持状态，不能因名称变化扩大产品支持范围。

```text
<!-- npu="950" id1 -->
- Ascend 950PR&950DT系列产品：支持/不支持
<!-- end id1 -->
<!-- npu="A3" id2 -->
- Atlas A3系列产品：支持/不支持
<!-- end id2 -->
<!-- npu="910b" id3 -->
- Atlas A2系列产品：支持/不支持
<!-- end id3 -->
<!-- npu="310b" id4 -->
- Atlas 200I/500 A2推理产品：支持/不支持
<!-- end id4 -->
<!-- npu="310p" id5 -->
- Atlas推理系列产品AI Core：支持/不支持
<!-- end id5 -->
<!-- npu="310p" id6 -->
- Atlas推理系列产品Vector Core：支持/不支持
<!-- end id6 -->
<!-- npu="910" id7 -->
- Atlas训练系列产品：支持/不支持
<!-- end id7 -->
```

## 全文差异化描述

- 非表格段落只要表达产品差异，必须在完整描述前后添加配对注释；即使该段用“该产品”“仅此平台”等代称，也不能省略标签。产品分组标题及其所属约束一起放入对应标签内。
- 起始注释必须为 `<!-- npu="950" id8 -->`，结束注释必须为 `<!-- end id8 -->`。仅替换 npu 值及正整数序号，内部空格严格保持一致；推荐注释各占一行。
- npu 只能是 950、A3、910b、910、310p、310b，大小写敏感。每个起始 id 在单篇最终文档中唯一，结束 id 与其配对；禁止嵌套、交叉、空内容或缺失结束注释。
- 同一 npu 可出现多段，但必须使用不同 id。涉及不同 npu 的差异描述拆成独立段落逐一标注；不得用一个 npu 标签包裹另一个产品的约束。
- 表格中的差异描述无需强制添加标签；表格内产品名仍必须采用规范名称。无需为跨产品通用且不表达差异的说明虚构产品范围。
- 支持列表沿用上方编号；其后段落继续使用未占用的 id。
- 正文可在有证据时使用上表的训练、推理及 PR/DT 子系列名，但不增删第1章固定产品项。原通用 Atlas 推理系列产品的描述使用“Atlas推理系列产品AI Core、Atlas推理系列产品Vector Core”；已有明确 AI Core 或 Vector Core 范围必须保留，不得扩展到另一类。

## 生成与校验

生成前按此规则组织标签；审阅时扫描全文标签并核对每段描述的产品范围。最终化工具规范展示文字中的旧产品名称，并检查支持列表标签、列表格式、标签格式、配对、唯一性、npu 值及标签内表格外的显式产品名映射。正文仅提到产品名不等于存在产品差异，不因缺少标签自动拒绝通用说明。所有非表格差异段落是否遗漏标签（包括显式产品名、代称和隐含条件），必须由生成与审阅阶段结合代码证据确认；程序不猜测语义或补造范围。表格豁免只覆盖单元格，HTML 表格必须闭合。
