# AscendC 最终文档生成

先按 `references/api-scope.md` 判断规则适用范围。Tensor/TPosition、寄存器、线程或队列等字段仅在当前成员实际涉及时核验；不适用项明确记录“不适用”，不要求构造对应对象。Tensor 参数需要时再读取 `references/tensor-parameters.md`。

## 前置条件

只在 `resolution.md` 已冻结时生成。先读取：

- `manifest.json`：标题、要覆盖的成员函数、调用约定和输出目录；
- `code-evidence.md`：精确原型、可验证代码事实和示例证据；
- `reference-evidence.md`：资料定位，仅用于理解已被决议的候选；
- `resolution.md`：唯一的规范事实、用户自定义结论、暂缓项和覆盖状态；
- 本次已核验的公开术语来源（如有）；没有对应来源时保持源码标识和准确含义，不加载历史词表作为规范。

不得在生成阶段重新读取原始已提供资料、宽泛扫描代码或引入新的事实。发现必需信息不足时，回到 `tasks/supplement.md`；发现事实冲突时，回到 `tasks/reconcile.md` 的 `question` 关口。

生成前读取 `resolution.md` 的“对外事实映射”。每条标为“写入正文”的事实必须出现在指定章节并包含全部必含标识符；标为“用户明确暂缓”的事实保留 `【待开发补齐】`。不得把测试覆盖、构建、编译、运行、golden 或验证状态写入任何正式 API 章节。

文档只能包含 `manifest.targetApi` 中列出的成员函数，并且必须符合其中的调用约定。先检查 `reference-evidence.md` 的“资料适用性”表和 `resolution.md` 的“下层资料适用性”“调用示例组成依据”表：`other-api` 和 `excluded` 资料不能提供任何当前 API 的技术结论、原型、参数、约束、公式或调用示例；`mixed-api` 资料只能使用表中明确属于当前 API 的 R-ID；`downstream-api` 资料只有逐条标为“写入当前 API 文档”或“经用户确认写入当前 API 文档”的 D-ID 才可影响正文；`peer-api` 资料只可提供调用示例的工程结构模板，不能提供目标 API 的调用、参数、输入、结果或技术结论。最终正文不暴露本地路径、源码位置、证据 ID、内部 helper/intrinsic、`Impl`/`Cal`/`*_impl`、寄存器或生成过程。

## 输出方式

先在内存中完成生成与 `tasks/review.md` 审阅；审阅通过后才写入：

```text
<outputDir>/<documentFileStem>_YYYYMMDDHHmm.md
```

`documentFileStem` 读取自 `manifest.output.documentFileStem`；旧清单未提供该字段时，按 `WORKFLOW.md` 中的符号运算符语义命名规则推导，不能使用百分号编码目录名。它仅用于产物文件名，正文标题、函数原型和代码检索仍使用原始 `documentApiName`。不持久化 `3_generate.md`、`4_review.md` 或其它草稿。文件名时间戳由调用方创建；若最终化脚本需要规范化，再以该同一文件作为 `--document` 参数。

生成和审阅完成后，将正文写入最终命名文件，先运行 node tools/ascendc-finalize.mjs --output-dir <outputDir> --document <最终文档.md> --check。该预检只在内存中执行规范化与全部最终化校验，不写入文件；根据预检结果修正正文或回到前置关口。预检通过后才运行不带 --check 的最终化。不得为通过校验添加无技术意义的注释、包装函数或示例代码；有效代码被误拒时应报告校验器问题。

## 固定章节

文档必须依次包含，且不带数字编号：

```text
# <documentApiName>
## 产品支持情况
## 功能说明
## 函数原型
## 参数说明
## 返回值说明
## 约束说明
## 调用示例
```

`参数说明`、`返回值说明`、`约束说明` 确无内容时，正文只能是一行“无”。有内容时不得同时保留“无”。

### 空章节格式

无返回值（void）时，`## 返回值说明`章节正文只输出单独一行“无”。没有可输出的用户可见约束时，`## 约束说明`章节正文只输出单独一行“无”。参数说明为空时同样只输出“无”。禁止写成“无。”、“- 无”或附加解释；除空章节正文“无”外，完整描述必须加标点符号。

## 产品支持情况

以下固定注释、`npu` 值、`id`、产品名称和顺序必须逐字保留；每项只替换为“支持”或“不支持”。不得合并、增删、改成表格，或写内部芯片标识。

```text
<!-- npu="950" id1 -->
- Ascend 950PR&950DT系列产品：支持/不支持
<!-- end id1 -->
<!-- npu="A3" id2 -->
- Atlas A3系列产品：支持/不支持
<!-- end id2 -->
<!-- npu="910b" id3 -->
- Atlas A2系列产品：支持/不支持
<!-- end id3 -->
<!-- npu="310b" id4 -->
- Atlas 200I/500 A2推理产品：支持/不支持
<!-- end id4 -->
<!-- npu="310p" id5 -->
- Atlas推理系列产品AI Core：支持/不支持
<!-- end id5 -->
<!-- npu="310p" id6 -->
- Atlas推理系列产品Vector Core：支持/不支持
<!-- end id6 -->
<!-- npu="910" id7 -->
- Atlas训练系列产品：支持/不支持
<!-- end id7 -->
```

仅根据已冻结的产品事实填写。成员或 overload 的产品差异在函数原型、参数或约束中按适用范围说明，不能修改总体列表。

未核验的产品不得标注支持，也不能把未找到证据视为不支持；缺少必需产品事实时返回补证或确认关口，不凭固定列表填写结论。

## 功能说明

用简洁的规格说明式语言写用户可感知的行为、使用效果和使用方式；参数首次出现时解释其含义。多场景用短段落或无序列表的加粗短语区分，不新增场景标题。

- 仅在规范事实明确给出用户可见计算关系时输出公式；内部调用、intrinsic 或 helper 不能作为公式。
- `$$` 公式边界各自独占一行，且公式后解释全部符号、下标语义与范围。
- 不为控制参数、地址偏移、步长、重复次数、mask、axis 或 shape 伪造数学公式。
- 编译限定符和内部管线标记只可留在函数原型代码块；不得翻译为未经证实的流水线术语。
- `【待开发补齐】` 和 `【需开发确认】` 只能按 `resolution.md` 的最终值保留，不能消除或扩写。

## 函数原型

- 逐字使用 `code-evidence.md` 中的完整签名，覆盖全部成员和 overload；每个声明独占物理行并保留分号，模板行与调用约定不变。
- 完整保留声明后缀，包括限定符、noexcept 和尾置返回类型；无法可靠定位声明边界时报告能力边界，不删去后缀后继续交付。
- `## 函数原型` 下禁止三级标题。可按真实函数名或有代码证据的用户可见模式用普通无序列表组织；没有模式证据时只按真实函数名组织。
- 禁止用代表性原型、“其余类型相同”、参数集合或模型自造版本名压缩原型。
- 不输出头文件、文件路径或证据说明。

## 参数、返回值和约束

非 void 返回值须说明已冻结事实中的含义及适用的错误返回或异常行为；没有证据时不臆造错误码或异常，必需事实缺失则返回补证。void 的返回值章节仍按空章节规则写“无”，有证据的相关错误行为写在适用的约束中。

参数说明按实际原型覆盖全部模板参数和形式参数：

使用下列固定表头；表中事实仍只来自冻结决议：

**表 1** 模板参数说明

| 参数名 | 描述 |
|---|---|
| <code>...</code> | ... |

**表 2** 接口参数说明

| 参数名 | 输入/输出 | 描述 |
|---|---|---|
| <code>...</code> | 输入/输出 | ... |

涉及多参数类型组合时，使用实际参与参数名作为全部列。涉及源操作数<code>src0</code>、源操作数<code>src1</code>和目的操作数<code>dst</code>的三参数组合，表头保持：

| 源操作数src0 type | 源操作数src1 type | 目的操作数dst type |
|---|---|---|
| ... | ... | ... |

- 模板参数使用两列表；接口参数使用“参数名 / 输入/输出 / 描述”三列表。不同 overload 的同名参数语义、单位、范围或约束确实不同时，才按已证实的功能模式或真实函数名拆表。
- 参数名、类型和字面量使用 `<code>...</code>`；表格使用简洁 Markdown，禁止 HTML 表格、LaTex 公式和 Markdown 行内反引号。
- 描述中包含含义、单位、范围、产品限制或暂缓项时以 `<br>` 分行；不把多个语义挤成推测性长句。
- 不得把内部变量、关联接口独有参数或隐含操作数伪造成形式参数。已证实的隐含语义应写在控制它的形式参数描述中。
- 不同产品或原型的 dtype、参数组合和跨参数约束必须完整分组列出；不得用并集、增量式“额外支持”、同上或自造“标准组合”取代事实。
- `约束说明` 只保留跨参数组合约束和未在参数表完整表达的全局约束；不重复单参数说明。
- 当前参数确实涉及 Tensor/TPosition 时，分别表达其对象类型、逻辑位置和有证据的物理存储。没有 TPosition 证据时，不能由 `LocalTensor`/`GlobalTensor` 类型推断数据通路或 Buffer。

## 调用示例

按成员遵循 `resolution.md` “调用示例组成依据”表的“示例来源”行：第一优先级是代码仓 `examples/` 中经核验的当前成员调用，包括确定性提取的 `Compute()` / `Process()`，以及按 `tasks/example-call-chain.md` 核验的 Helper 调用链或 Helper 片段；第二优先级是 `current-api` 资料或 `mixed-api` 中明确属于当前 API 的经核验示例；两者都不存在时，才依据当前 API 的精确原型、可达实现和冻结事实构造示例，并将“示例来源”记录为“当前 API 实现与同类 API 结构”。第三种情况下可最多参考一份 `peer-api` 资料的工程、Host、Kernel 或 CMake 组织方式，但不得复制其 API 调用、参数、输入值、结果、约束或行为描述。`downstream-api`、`other-api` 和 `excluded` 资料不能成为当前 API 调用示例的来源。所有目标 API 内容仍须重新依据当前 API 的精确原型和冻结事实填写。

- 核心调用必须覆盖需要示例覆盖的文档成员，参数个数、类型、顺序和调用约定与原型一致。
- 示例不得包含省略号、伪地址、未声明变量、未初始化地址空间指针或待补齐占位参数。
- 生成前逐项读取 `resolution.md` 的“示例使用限制”和“调用示例组成依据”。每一段代码、每项输入和结果说明都必须有表中允许的依据；同类 API 资料只允许支撑结构行，不能支撑目标 API 行为或数据。示例中的输入值、参数组合、地址关系、状态和结果说明只能落在“示例只能使用”的范围内；不得使用“不得使用”列中的条件，也不得写入“校验写法”列中的字面量或表达式。
- 若某个会影响示例的未证实行为没有具体允许范围，返回 `tasks/supplement.md` 补证；不得选择看似普通的数值、默认状态或模糊变量名来规避该缺口。
- 仅在代码事实明确表明依赖输出原值时初始化输出；不得为了示例而臆造清零。
- 通过队列或缓冲区分配的 `LocalTensor`（包括临时 Buffer）必须在示例末尾释放，或有已证实的框架管理说明。
- 示例后必须有“结果示例如下：”及 `text` 代码块。只写代码或决议能证明的数值、关系、shape 或存储位置；不能编造数值。

## 通用格式边界

- 全文采用有可追溯来源且适用当前版本的术语，使用产品规范中的全称，禁止内部芯片标识、代码目录、文件路径和证据措辞。
- 正文中不用 Markdown 反引号行内代码；用 `<code>...</code>`。C++ 与 text 围栏代码块保留原样。
- 不输出思考过程、来源比较、冲突说明、待办解释或阶段总结。
- 不为追求文档完整度修改用户确认的最终值，也不得填补用户已暂缓的槽位。

生成或审阅前读取并遵守 `references/product-document-format.md`；其中定义产品名称、支持列表和差异化标签规范。
