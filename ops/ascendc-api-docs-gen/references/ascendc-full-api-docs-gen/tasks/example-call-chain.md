# Helper 调用链样例回退

先按 `references/api-scope.md` 判断规则适用范围。Tensor/TPosition、寄存器、线程或队列等字段仅在当前成员实际涉及时核验；不适用项明确记录“不适用”，不要求构造对应对象。Tensor 参数需要时再读取 `references/tensor-parameters.md`。

## 触发条件

仅当临时代码阅读清单的某个 `callExample.members[]` 同时满足以下条件时执行：

- 状态为 `unavailable`；
- 存在非空 `helperCandidates`；
- 确定性提取尚未找到包含目标成员直接调用的 `Compute()` 或 `Process()`。

已有确定性 `Compute()` 或 `Process()` 结果时不得执行本回退，也不得用模型替换它。

## 受限核验

对每个成员，按 `helperCandidates` 的顺序处理；只读取候选记录指定的 `.asc` 文件。该文件可以完整阅读以定位本地调用者，但不得为样例回退扫描其它 `examples/` 文件、资料文件或同名 API。

模型只可建立同一文件内、源代码明确可见的调用边：

- 从记录的 `functionName` 中已定位的目标 API 直接调用开始；
- 向上寻找调用该函数的本地具名函数；
- 每一跳必须在调用者函数体内出现显式调用，并且能唯一对应当前文件中的被调函数定义；
- 最多向上追溯四条调用边，目标是 `Compute()` 或 `Process()`。

函数指针、对象或指针成员的未解析调用、宏间接调用、模板或重载无法唯一对应、条件分支无法确定或跨文件调用都不得猜测为调用边。遇到这些情形即停止上溯，并记录原因。

若 `helperCandidatesTruncated` 为 `true`，列出的候选只是按脚本排序后的前若干项；即使这些候选均无法核验，也不得写成“仓内不存在调用示例”，只能记录“受限候选未能核验”，再按正常优先级继续寻找资料或构造示例。

## 结果记录与使用

在 `code-evidence.md` 的“调用示例”节中，对每个处理成员记录：文件完整路径、确定性候选函数及行范围、目标 API 调用行、已证实调用链、核验方式和停止原因（如有）。

- 若链到达 `Compute()` 或 `Process()`，记为“代码仓 examples（Helper 调用链已核验）”。只能引用链上原始函数范围；不得把分散的函数改写或拼接成宣称可独立构建的工程。
- 若目标 API 的直接调用位于已核验 Helper 中、但未能安全追到入口，记为“代码仓 examples（Helper 片段）”。它可证明该片段中的目标 API 调用，不能证明 Host、构建、输入、结果或完整工程行为。
- 若候选函数本身或目标调用无法核验，且候选列表未截断，才记录代码仓没有可用示例，并进入资料回退。

无论结果属于哪一类，调用示例中的参数、输入、结果和行为仍须满足当前 API 的精确原型与“示例使用限制”；不能从调用链存在推导未出现的行为或约束。
