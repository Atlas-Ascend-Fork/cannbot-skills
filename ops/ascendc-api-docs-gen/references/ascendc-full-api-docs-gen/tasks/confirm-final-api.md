# 确认最终文档接口

在读取任何资料、运行调用关系分析或打开目标代码之前，确认本次**最终要生成文档的接口**。这一步只确认最终文档对象，不是询问下层 API、同类 API 或参考资料的用途。

先完整读取 `manifest.json`，检查 `finalApiConfirmation`：

- 状态为 `confirmed`：继续后续流程，不重复询问。
- 状态为 `pending`：必须使用 `question` 让用户确认，不能根据资料名称、调用关系或文件路径猜测。

提问工具不可用时按 WORKFLOW 的确认规则用等价结构化提问或普通对话取得明确回答；确认内容与记录要求不变，不能因缺工具跳过确认或从含糊答复推断同意。

问题必须清楚展示：

- 接口名称；
- 接口类别；
- 调用方式；
- 本文档覆盖的成员函数；
- 声明或定义文件。

推荐问题正文：

> 本次最终将生成以下接口的参考文档。请确认这就是你要写的接口；下层 API 和同类 API 文档只会作为资料，不会替代它。
> 名称：…
> 类别：…
> 调用方式：…
> 覆盖成员：…
> 接口文件：…

选项包含“确认该接口”和“不是该接口”；保留 `Other / 自行输入`。用户确认后执行：

`node tools/ascendc-confirm-target-api.mjs --manifest <manifest.json> --api-id <targetApi.id>`

然后重新读取 `manifest.json`。若用户否认或补充的信息指向不同接口，停止当前任务；应由调用方或直接入口创建该接口的新清单，不能在原清单中替换 `targetApi`，以免覆盖此前资料与确认记录。

只有确认完成后，才能运行调用关系分析、寻找仓内候选文档、登记资料用途、读取代码或资料。
