# 生产执行约束

每次实现检视均读取。规则以调用方规格、设计及 [生产代码规范](../../cannbot-dsl-best-practice/references/production-code.md) 为依据，不用关键词扫描代替调用链核实。

## 取证与结论

从公开入口追踪到实际主计算，包含 helper、别名、装饰器、注册/适配层、输出及 workspace 分配、数据搬运和每次设备启动。记录参数设备、触发条件、真实函数和准确代码行；有动态分派时逐个核对受支持的生产分支。

确认违反下列约束即判 FAIL，严重度 high；注释说明、命名惯例或普通数值通过不能抵扣。只发现可疑调用且无法确定执行效果时写待确认，说明需要的源码、编译或设备证据。报告中区分“源码检查通过”和“设备证据已验证”，不能以没有采集到记录证明没有设备任务。

## DSL-E01：额外 torch 设备算子

- 禁止算子通过 torch 函数、Tensor 方法或 torch.ops 下发额外设备算子来补算、初始化、复制或转换结果，包括包装在 helper/注册函数中的调用。
- Host CPU torch、元数据读取、未初始化分配及已确认的零拷贝视图允许。`zeros` 需核对 device；`reshape/contiguous/to` 需核对具体输入下是否发生复制/转换。不能只因出现 torch 就判 FAIL，也不能因代码位于 Host 函数就豁免。
- 不限制设计所需的自定义 DSL Kernel 数量。C/V 协作、多核与必要同步按设计检查；明确要求的 metadata 前置接口独立记录职责及成本。
- 核对当前版本、固定输入和设备的 msprof 原始记录，覆盖预热后的完整公开入口。列出设备任务与源码启动点的对应关系，确认无 torch 额外小算子；不能只截取目标 Kernel、只按名称筛选或拿加速比例代替检查。

## DSL-E02：测试诊断进入正式路径

算子不包含 probe 内容或目录，不为验收写事件、trace、计数、克隆输入或同步回读。关闭开关不代表相关操作消失。确认分配/复制/回读的真实用途，计算所需 workspace 和同步保留；输入不变性由测试侧检查。禁止为证明 metadata 已消费额外启动检查 Kernel，单独验证公开 metadata 接口及主算子的真实消费路径。

## DSL-E03：合法输入的占位结果

对照规格遍历受支持的布局、dtype、属性和可选输入组合，确认输入参与计算且结果被实际写入。合法分支直接返回零值或未实现结果判 FAIL；数学定义要求的零结果须给出对应条件。显式拒绝尚不支持的组合必须同时报告规格覆盖缺口，不能将拒绝当成完整支持。

## DSL-E04：运行与导出的主计算一致

核对精度和性能入口、导出回调、编译工厂及 Native 产物实际覆盖同一主计算和声明变体。报告真实调用链；不能以子程序成功导出、装饰器存在或 Native 日志中的命中字样替代完整算子验证。缺少当前版本的主计算 Native 证据时保持待验证。

## DSL-E05：Kernel 运行时打印

禁止 Kernel 设备运行时打印，覆盖别名和设备 helper；确认生成设备打印操作即判 FAIL，默认关闭的打印分支也须移除。Host 普通打印允许；构建或编译阶段的 Python 输出须确认不生成设备操作，不能只按 print 字符串判定。检查设备 Tensor 格式化是否引起回读或同步，记录实际调用链与执行阶段。对 Host 日志单独计入入口测量，不误报为 Kernel 打印。

## 报告证据

每项执行约束发现至少列出：规则 ID、结论、入口至违规操作的调用链、触发输入/设备、代码位置、实际副作用、修复建议和回归方法。动态证据再记录实现版本、命令、退出码及原始记录位置。执行证据不齐或仍有 FAIL 时，生产执行门禁不得通过；可读性结论单独保留。
